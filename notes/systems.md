## 5e. Maps from Blender files + terrain height (2026-10-18, protocol `v24`)
- **Rules for the map team:** `MAP-DESIGN.md` (naming `ground`/`floor_`/`col_`/`colv_`/`bounds`/`spawn_`/`prop_`/`bld_house_`/`env_`/`light_`/`anim_`, collection custom properties, budgets). First real map: **`valley`** (another session built it: `assets/src/maps/valley_build.py` + `valley.blend`, design `designs/maps/valley.md`).
- **Export:** `assets/src/maps/map_export.py` (run in Blender: `MAP_ID="valley"; exec(open(path,encoding="utf-8").read())`) → `assets/maps/<id>.json` (gameplay) + `<id>.glb` (visual, Draco, anim_ actions) and bumps `manifest.json` `"maps":{id:{file,data,v}}`; also runs `map_check.py`. JSON: `W,H` px, `c` grid spacing px (10 = 0.5 unit), `nx,ny`, `g` = ground heights as base64 int16 cm (−32768 = none), `fl` floors `{x0,y0,nx,ny,top,bot}`, `obs` circles `{x,y,r,hgt,k}` (`col_` boxes → chain of circles; hgt = top − ground at centre), `spawns` (`t` 0 = blue / 1 = red), `espawn`, `rings`, `tasks`, `props` (omitted = random props), `houses {x,y,w,d,ry}` (w = 160·scaleX, d = 130·scaleY, ry = Blender rot Z), `lights`, `env` (1-unit bit masks), settings `name/desc/sky/fog/modes/random/weather/music`. Coordinates: game x = (bx+W/2)·20, y = (H/2−by)·20.
- **Game load:** `loadAllMapData()` at page start fetches every map JSON in the manifest → `regFileMap` puts it in `MAPS[id]` (with `.terr`, `.fm`) and `RANDOM_MAPS` (unless `random:0`); id equal to a code map replaces it. Clients that get a map id they don't have yet wait (`mapReady`) and load it. `mapOkFor(id,mode)` filters the random pick by `modes`. Spawns/team spawns/enemy spawns/race rings/tasks/props come from the file when present (`fmap()`, `spawnPts`, `teamPts`).
- **Heights — the one rule:** sim heights stay **"height above the ground layer"** (`p.z`, `e.h`, `pr.h`, effect `h`), so every existing spell works unchanged; the real 3D height is `terrT(x,y)+z`. `TERR` (set in `setMapVars`) = `{c,nx,ny,g,fl}`; `terrT` bilinear ground height; `groundH(x,y,z)` = standable surface (floors within `TSTEP` 1.1 of the feet + glaciers); `terrMove(o,ox,oy,z,onG)` after moving: slope > `TSLOPE` 1.6 (~58°) uphill = wall (slides along x/y), downhill on foot sticks to the slope, walking off a cliff falls; projectiles keep a straight world line (`pr.h -= Δground` each step) and die in `terrSolid`; file `col_` obstacles carry an absolute `top` and are compared against `terrT+z` (collision, projectiles, aim). Aim: `eShoot`/minion/auto-lock add the ground difference; crosshair raycast `rayTerr` hits terrain and sends `INPUT.ah` relative to the shooter's ground. **When you add code that places a 3D object from game coordinates, add `GY(x,y)` (or `TW(X,Z)` in 3D coords) to its y** — done for players, enemies, minions, projectiles, particles, shapes, lines, bolts, zones, ice floors, glaciers, props, houses, slashes, efx meshes, name/number projection, camera; lights in `LREQ` get it in the light pool unless `abs:1`.
- **Client world:** `buildFileMap(id)` = fog/light from the file, fallback grass terrain mesh from the grid (`terrGeo`) + floors + grey cylinders for `col_`, then swaps in the `.glb` (`batchStatic`, `anim_` objects skipped and played by an `AnimationMixer` in `animateWorld`, `ns` extra = no shadow), `light_` → `world.userData.lights` pushed into the light pool each frame. Camera stays above terrain and pulls in when a hill is between it and the player.
- Verified 2026-10-18 in the browser pane (solo + bot, FFA and Co-op on `valley`): map loads and is in the random list + lobby picker, south hill climbable (to 3.8), north cliff blocks players and goblins, bridge ramp → deck at height 2.0 → down the other side, walk under the bridge along the stream, stream crossing, shots fly straight and stop at the cliff face, goblins follow over hills, bot on the bridge renders at y 2.0, no console errors; valley 72 draw calls (meadow 116, Hogsmeade 276). **Not checked:** two real devices, enemies that leap/fly over cliffs, BR zone / race / Voldemort on a file map, weak-PC frame time.

## 5d. Destructible buildings (houses) (2026-10-18, protocol `v23`)
- **2026-10-20 (protocol `v28`): rewritten as 54 chunks per house (Battlefield style) — the current design is in `Destruction.md`.** The notes below describe the original 6-piece version; piece names, elements, `damageEnv` and the event shape still apply, but HP/collision/snapshot are per chunk now.
- **What:** every `OBS` entry with `k:'house'` (Hogsmeade 14 houses + 2 test houses in Test Place, west side) is split into 6 pieces `BLD_PIECES` = `wall_front` (door, local +y/+z) `wall_back` `wall_left` `wall_right` `roof_left` `roof_right`. Each piece has its own HP (`BLDDEF.house.hp` wall 80 / roof 60 — placeholders for the gameplay side). A piece at 0 HP breaks alone → the house breaks where it was hit; 3 walls broken = both roofs collapse.
- **Host:** `genBldg(map)` (in `setMapVars`, sets `o.bi` on the OBS entry) → `BLDG[i]={o,D,c,s,pc:[{hp,fl,burnT,frzT}]}`; `BLDON` = same modes as props (off in quid/race/imp). Local frame helpers `bldLocal/bldWorld/bldRect/rectDist`. `hitBldPiece(b,j,dmg,el,ox,oy)`, `breakBldPiece`, **`damageEnv(x,y,r,dmg,by,el,h)`** = the one call for spells (props + house pieces in the circle; roofs only if `h+r/20 >= wall height`). Elements `el`: `fire` (burn 5 s at 6 HP/s, then charred), `ice` (×0.7, frozen 6 s → other hits ×2, ice puts fire out, fire melts ice), `blast` (×1.5), `fireblast`. Projectiles: `bldPieceAt` (below wall height = nearest wall, above = roof pyramid) → `hitBldPiece` with `projEl(pr)` (type name or owner path). Collision `collideBld` = oriented rectangles per intact piece (broken wall = walk inside; roofs block only flyers); house OBS circles are skipped in `collideWorld` / projectiles. `updateBldg` (in `updateSpells`) ticks burn/freeze.
- **Wired spells:** `explode` (fire), `pyroBigBoom` + `dragonfallBoom` (fireblast), `frostBoom` + `frostSlam` (ice), boss `bombTick` (blast). This also means those AoE spells now break crates/barrels (the old open question "which AoE spells call damagePropsIn").
- **Network:** snapshot `BD` = one hex char per piece (bits 1 broken, 2 charred, 4 burning, 8 frozen; `''` = all clean), clients copy it in `onSnap` (`!NET.isHost`). Events `{k:'bld',e:'h'|'b',i,p,el,x,y,ox,oy,h}` → `fx` case `'bld'` (dust/fire/ice bursts, sounds, shake) + `bldDebris` (local-only flying chunks away from `ox,oy`, max 180, `updateDebris`, `clearDebris` on map change/new round).
- **Client:** `syncBld(dt)` (frame loop) keeps one group per house in `BLDV`, rebuilt only when broken/charred bits change (key string) and merged with `batchStatic` per house (~7 draw calls/house; before, all houses were merged map-wide). Frozen = hidden ice shell boxes shown per piece; burning = particles/lights per frame. Code-built pieces `bldFallback` (half-pyramid roof `halfRoofGeo`), charred = `charMat` (darkened cached clone). `buildHogsmeade` skips houses that have `o.bi`.
- **Model file (optional):** manifest `bld_house` = one .glb with objects named like the pieces (+ `_broken`), nominal size 8 × 6.5 (`BLDDEF.bw/bd`), scaled per house in x/z (`bldFilePiece`). Missing piece → code piece. Debris files `debris_stone` (walls) / `debris_wood` (roofs). Rules for the modeler: `ASSETS.md` §3b. Skill designers: `SKILL-DESIGN.md` "การโต้ตอบกับสภาพแวดล้อม".
- **First real house file (2026-10-18):** `bld_house` → `assets/buildings/house.glb` (45 KB **Draco**, 4,184 tris for all 12 pieces = 6 intact + 6 broken; half-timbered Hogsmeade style with gable roof split at the ridge, snow, glowing windows + attic window, door lantern, chimney on `roof_right`, fireplace on the inner side of `wall_back`; 1 material `house_mat` = 64 px palette + emission texture). Debris `debris_stone.glb` (5 chunks) / `debris_wood.glb` (planks, tiles, snow lump), ~8 KB each. Source: generator **`assets/src/house_build.py`** (run in Blender: `exec(open(path).read())` → builds scene `house_build` and exports all three; export uses `collection=` because selection-based export also grabbed the default Cube of another scene) + `assets/src/house.blend`. Verified in Hogsmeade FFA: all 14 houses load from the file, broken pieces/charred look/debris from files work, no console errors. The file has one wall colour for every house (code houses had 4).
- Debug: `WD.BLDG`, `WD.BLDON`, `WD.damageEnv`, `WD.hitBldPiece`, `WD.breakBldPiece`.
- Verified 2026-10-18 in the browser pane (solo, Test Place + Hogsmeade FFA): fire/ice/blast pieces change state and look, debris flies, a player walks in through a broken wall and stops at the back wall, projectiles hit the nearest wall / the roof by height, new round on the same map restores houses, no console errors. **Not checked:** online client (BD over the network), frame cost on a weak PC, real Blender house file.

## 5b. Skills system (rewritten 2026-10-17/18 — "paths × spells")
**Design (user's brief):** many spells, element spells with side effects, crowd control, summons, split into "paths" (สาย), balanced. Chosen: pick **1 main path (สาย)** → gives the **ultimate (X)**; fill **Q/E/R/F** from the spell library (max **2 off-path** spells); **6 paths × 6 spells = 36** (5 normal + 1 ult per path).
- Data: `PATHS`, `SPELL_LIST`, `SPELLS` (`defSpell(path,{id,n,ic,cd,d,fx,cast(p,S),hit(pr,t),ult})`) — **append-only** (index = position; kit string `path.q.e.r.f` uses indices). Kit helpers: `parseKit/cleanKit/setKit/kitSpells`, host-side `p.kit/p.kitIds/p.ultId`, client `KITS[id]`/`getKit(id)`. Kit travels in `hello.kit` + lobby `players[].kt`; lobby change = `{t:'kit',k}`.
- Cast: `castSlot(p,i)` (cooldown `p.cd.q/e/r/f`, silence, BR unlock via `BRMAP`), `castUlt(p)`. HUD slots come from `mySlots(me)`.
- **Statuses** (players + enemies + minions): `addStun/addRoot/addFreeze/addSlow/addChill/ignite/shock/addPoison/addSil/addFear/addBlind/addMark/addWard/knock/healT`, ticked by `tickStatus`, speed by `moveMul`, CC duration scaling by `ccScale` (bosses 25 %, big 40 %, players get diminishing returns 100/60/35/20 % within 6 s), bitmask `fxMask` in the snapshot (`fm` on P/E/MN). Combos: fire on chilled/frozen = **melt** (+6, clears chill/freeze), ice shard/zap on frozen = **shatter**, shocked takes +8 % (zap +60 % and short stun), marked +25 % & half healing, poison reduces healing 15 %/stack, frozen +15 % damage.
- Field objects: zones `addZone` (`G.zones`, `hit`/`allyHit`), delayed strikes `addStrike` (telegraph via `tele` event with `col`), walls `addWall` (`G.walls`, snapshot `WL`, block movement + enemy projectiles), channels `G.chan` (tempest). Minions `G.mins` (snapshot `MN`), AI `updateMins`, types in `MIND` (wolf/sprite/golem/wisp), targetable (`foesOf` includes enemy minions, projectiles hit them, coop enemies may target them), HP bars `drawMinBars`.

- Kit UI: creator **step 3 "คาถา"** (paths grid, 4 slots + fixed ult, library tabs, description box) + lobby button `#btnKit` (kit-only mode `crKitOnly`). Stored in `localStorage wd_kit`.
- **Balance tools (console only):** `WD.dmgTest()` (per-spell damage/CC vs a dummy over 8 s), `WD.bal(kitA,kitB,rounds,maxT)` (bot duels, sides swapped), `WD.tour({name:kitStr,...},rounds,maxT)` (round-robin win rates), `WD.balArena(false)` restores obstacles, `WD.hostTick(dt)` for headless sims. `botBrain` = simple kiting bot (aim lead, cast when in range, shoots minions that are close). **Sim caveats:** bots never dodge/shield and don't walk around walls/golems, so wall/minion/CC kits are over/under-rated — use sims to find *outliers*, then tune by feel with real players.
