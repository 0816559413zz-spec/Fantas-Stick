# วิธีทำงาน VFX กับผู้ใช้ — ส่งต่อจากแชท 2026-11-01

อ่านคู่กับหน้าแรกของ `HANDOFF.md` ก่อนทำงานต่อ ข้อกำหนดล่าสุดของผู้ใช้ในแชทมีผลเหนือคู่มือเก่าที่ให้ bind/commit/push โดยอัตโนมัติ

## การคุยและการเลือกขอบเขต

- **ตอบภาษาไทยเสมอ** แม้ผู้ใช้จะพิมพ์อังกฤษ ผู้ใช้มักดูผ่านโทรศัพท์: อธิบายพอเข้าใจ แต่ไม่ยาวเป็นบทความและไม่สั้นจนเหลือแค่คำรับปาก
- เริ่มบอกสั้น ๆ ว่าจะอ่าน/ปรับอะไร แล้วรายงานเมื่อมีสิ่งที่พบหรือเห็นภาพแล้ว อย่าปล่อยให้ผู้ใช้ไม่รู้ว่ากำลังทำงาน
- ถ้าผู้ใช้บอกว่า **คุย/วางแผนก่อน ยังไม่แก้** ให้เสนอภาพที่นึกไว้ก่อน ไม่แก้ไฟล์เอฟเฟกต์หรือเกม
- ถ้าผู้ใช้สั่ง **ลองทำ/ปรับตรงนี้** ให้ทำตัวอย่างในขอบเขตที่ตกลงได้เลย ไม่ถามยืนยันคำสั่งเดิมซ้ำ
- ทำทีละสกิลหรือทีละส่วนที่กำลังคุย รวม BA/Shield/Dash ด้วย เมื่อจบและผู้ใช้บอก next ให้เสนอส่วนถัดไปอย่างสั้น ๆ
- แยกสถานะให้ชัด: **ร่างภาพ → ตัวอย่างใน Studio → ผู้ใช้รับหน้าตา → ผูกเข้าเกม → ทดสอบจริง → เซฟ/ส่งขึ้น remote** การรับภาพไม่ได้อนุญาตทุกขั้นที่เหลือโดยอัตโนมัติ
- คำว่า **เซฟ** ใน workflow เดิมหมายถึง commit ในเครื่องเมื่อผู้ใช้สั่ง; **push ต้องมีคำสั่งแยก** จด handoff/สเปกได้ระหว่างทำงาน ไม่ต้องรอคำว่าเซฟ

## วงรอบออกแบบที่ใช้จริง

1. อ่านสถานะปัจจุบันจาก `HANDOFF.md`, สเปกธาตุใน `designs/`, และสกิล/ตัวสร้างที่เกี่ยวข้อง ใช้ `CODEMAP.md` หาโค้ด อย่าเดาวิธีใช้สกิลจากชื่อ
2. ถ้ามี storyboard ให้อ่าน `storyboard/sb-<id>.md` และภาพอ้างอิง/ภาพวาด/การเคลื่อนไหวทุกช็อตที่เกี่ยวข้องก่อน ใช้ `VFX-STUDIO-CLAUDE.md` อธิบายฟอร์แมต
3. เปิดดูภาพอ้างอิงจริง วิเคราะห์ **ทรง สัดส่วน ตำแหน่ง สี ความหนา การซ้อนชั้น และการเคลื่อนไหว** แยกกัน อย่าจับแค่คำว่า ink/น้ำ/สายฟ้าแล้วก็อปเอฟเฟกต์เดียวใส่ทุกสกิล
4. บอกแนวทางเป็นไทยสั้น ๆ เช่น ทรงหลัก + ชั้นผิว + อนุภาค + จังหวะท่า ไม่เปลี่ยนกลไก/ดาเมจ/คูลดาวน์ระหว่างทำ VFX โดยไม่ได้ขอ
5. เริ่มจาก **ภาพนิ่งของตัวอย่าง 3D จริงในเอนจิน** เมื่อทรงยังไม่ลงตัว เช่น หัวมังกร ให้แยกดูหัวก่อน ไม่รีบทำ GIF ทั้งสกิลทุกครั้ง
6. เรนเดอร์แล้วเปิดภาพตรวจเองก่อนส่ง ถ้าไม่เห็นทรงหรือจุดที่ผู้ใช้ขอ ให้แก้ก่อน ไม่ใช้คำว่าไม่มี console error แทนการตรวจภาพ
7. ส่ง **JPG/PNG/GIF เห็นในแชทโดยตรง** ใช้ภาพใกล้เมื่อดูผิว/ตา และภาพรวมที่มีตัวละครเป็นสเกลเมื่อดูขนาด ผู้ใช้ไม่ควรต้องเปิด HTML หรือกลับไปดูหน้าจอ PC เพื่อรีวิว
8. เมื่อคุยเรื่องการเคลื่อนไหว ให้ส่ง GIF จากการเรนเดอร์จริง ครอบคลุมช่วงเปิด/บิน/ชะลอ/ลอยรอ กล้องนิ่งและเฟรมต่อเนื่อง รอบมังกรปัจจุบันใช้ 30 fps, 9 วินาที ถ้าทรงถูกปฏิเสธ ให้กลับมาดูภาพนิ่งแก้ทรงก่อน
9. รับการแก้เป็นจุด ๆ และรักษาส่วนที่ผู้ใช้รับแล้ว เช่น ลดเขา/เลื่อนตา ไม่ควรเปลี่ยนทางบิน สีทั้งตัว หรือกลไกอื่นไปพร้อมกัน คำว่า ขวา/ขึ้น ในภาพหมายถึงมุมภาพนั้น; ทิศยิง/ทิศมังกรในเกมต้องเทียบกับทิศจริงของตัวละคร
10. บันทึกสิ่งที่รับแล้ว สิ่งที่ยังรอรีวิว และสิ่งที่ถูกยกเลิกให้แยกกัน อัปเดตสถานะหน้าแรกของ handoff แทนการเพิ่มคำว่า LATEST หลายรุ่นที่ขัดกัน ประวัติรายละเอียดเก็บใน `notes/` และสเปกธาตุ

## หลักงานภาพและแอนิเมชันที่ผู้ใช้เน้น

- ต้องดูมีพลัง มีทรงและเนื้อวัสดุ ไม่ใช่แค่แสงวงกลมหรือเส้นบาง ๆ และไม่ใช่อธิบายแค่ว่าอ่านระยะง่ายขึ้น
- น้ำปัจจุบันเป็น **painted/anime 3D** มีชั้นน้ำเงิน ฟ้า ไซแอน/เขียวอมฟ้า ขอบขาว โฟม และหยดน้ำ ไม่ซีดจาก glow ทั้งชิ้น และไม่เป็นริบบิ้นเรียบอย่างเดียว
- รักษาการไล่สีที่ผู้ใช้เลือก เพิ่มริ้วน้ำ/ชั้นผิวโดยไม่ย้อมทั้งตัวเป็นสีเดียว ภาพอ้างอิงไม่ใช่ข้อบังคับให้มังกรกลับไปขด S: ผู้ใช้ยกเลิกท่านั้นแล้ว
- เน้นคลื่นน้ำและรูปทรงเฉพาะสกิล ไม่เปลี่ยนผิวเป็นตาข่าย caustics หรือเกล็ด/เซลล์ซ้ำแบบที่ผู้ใช้เคยปฏิเสธ รอยโค้งที่เพิ่มในตัวอย่างล่าสุดยังต้องให้ผู้ใช้รีวิว
- การเคลื่อนไหวต้องมีชีวิตแต่ไม่สั่นทั้งตัว: หัวนำ ลำตัวตาม หางคลาย/สะบัดทีหลังได้ อย่าฝืนหมุนหัวหรือย้ายตัวให้ลงจุด standby เป๊ะ ๆ
- คำว่า **บินเร็วขึ้นแต่เวลาบินเท่าเดิม** คือเพิ่มการเดินทางในช่วงเวลาเดิม ไม่ตัด intro ให้สั้นลง
- Wing idle ของ Wind เคลื่อนนิดเดียว ท่ากระพือแรงใช้เฉพาะ action ที่เหมาะ ไม่เอาการทดลองกระพือทั้งเวลาจาก Studio ไปใส่เกมเอง

## ทำภาพและ GIF รุ่นปัจจุบันซ้ำ

ทำงานที่ `D:\Fantas-Stick`; ใช้ `python tools/serve.py` เมื่อยังไม่มี server ที่พอร์ต 8765 หรือผู้ใช้เปิด `VFX Studio.bat` ได้ อย่าเปิด server ซ้ำถ้าตัวเดิมทำงานอยู่

```powershell
# ทุกเฟรมของภาพรวม (สคริปต์เขียน shots/dragon_waterwrap_000.jpg ถึง 269.jpg)
node tools/headless.js --url "index.html?studio&fx=water/dragon_hover&at=self&map=test" --js tools/water-dragon-freecruise-preview.js --timeout 240 --quiet > shots/dragon-waterwrap-render.log 2>&1

# ภาพรวมมุมใกล้หนึ่งภาพ
node tools/headless.js --url "index.html?studio&fx=water/dragon_hover&at=self&map=test&poseview" --js tools/water-dragon-freecruise-preview.js --timeout 240 --quiet > shots/dragon-waterwrap-still.log 2>&1

# แยกดูหัวบนพื้นเรียบ ไม่ใช่รูปทรงทั้งตัว
node tools/headless.js --url "index.html?studio&fx=water/dragon_hover&at=self&map=test&headstudy" --js tools/water-dragon-freecruise-preview.js --timeout 180 --quiet
```

`&headview` เป็นภาพใกล้หัวในฉากจริง ส่วน `&headstudy` แยกเฉพาะหัว อย่าใช้สลับความหมาย ชื่อ output กำหนดอยู่ท้ายสคริปต์ เปลี่ยนชื่อรุ่นให้ชัดเมื่อทำรอบใหม่เพื่อรักษาภาพที่เคยส่ง

หลังคำสั่งเสร็จ อ่าน log (`Get-Content ... -Tail 30`) ให้มี `page errors: 0` แล้วเปิดภาพช่วงต้น/ช่วงเปลี่ยนท่า/ช่วงรอ อย่ารันขั้น pack ก่อน capture เสร็จ

```powershell
@'
from pathlib import Path
import shutil
folder = Path('shots/dragon-waterwrap-frames')
folder.mkdir(exist_ok=True)
for i in range(270):
    shutil.copyfile(Path('shots') / f'dragon_waterwrap_{i:03}.jpg', folder / f'frame_{i:03}.jpg')
'@ | python -
python tools/pack-wind-wing-preview.py --input shots/dragon-waterwrap-frames --output shots/dragon_waterwrap.gif --fps 30 --max-width 760 --colors 192
```

ชื่อ packer มาจากงาน Wind แต่ใช้รวมเฟรมชุดนี้ได้ ภาพ `shots/` ถูก git-ignore และอยู่ในเครื่องนี้ ถ้าต่อคนละเครื่อง/checkout แล้วไม่พบ ให้เรนเดอร์ใหม่จากสคริปต์ ไม่ถือว่าตัวไฟล์ GIF อยู่ใน commit

ส่งสื่อในแชทด้วย absolute path เช่น `![มังกรน้ำ](D:/Fantas-Stick/shots/dragon_waterwrap.gif)` และเปิดตรวจภาพ/เฟรมจาก GIF ที่เข้ารหัสแล้วก่อนส่ง

## สเปก โค้ด และการส่งงาน

- สเปก/คำตอบของผู้ใช้: `designs/water.md`; ประวัติงาน: `notes/CHANGELOG.md`; ตำแหน่งฟังก์ชัน: `CODEMAP.md`
- งานฐานก่อน prototype: `tools/water-dragon-gen.py`, `tools/water-tex-dragon.py`, `assets/src/water_meshes_build.py` §11, `assets/vfx/water_dragon*.glb`, `assets/fx/water/dragon_*.fx.json`, `js/68-water-view.js` อย่ารัน generator เก่าทับรุ่นที่กำลังออกแบบ
- เมื่อแก้ generated FX ให้แก้ตัวสร้างที่เกี่ยวข้องแล้วตรวจ `node tools/fx-check.js` (เขียน registry/docs อัตโนมัติด้วย) เมื่อแก้โค้ดให้ตรวจ `node tools/check.js`, `node tools/codemap.js` และ visual capture ที่ตรงจุด ไม่ต้องเรนเดอร์เกมใหม่เมื่อแก้เอกสารอย่างเดียว
- ถ้ามี storyboard ของงานนั้น ค่อยอัปเดต `storyboard/boards.json` ที่ board จริง พร้อม `fx/reply/status/result/note` แล้วรัน `python tools/serve.py --sb-md` อย่าเขียนทับ markdown ที่ generate หรือบอกว่าอัปเดต storyboard ทั้งที่แก้แค่สคริปต์จับภาพ
- **ไม่ bind / เปลี่ยนกลไก / commit / push อัตโนมัติ** ตามขั้นจบงานในคู่มือเก่า คำสั่งผู้ใช้กับขอบเขต Studio ที่ตกลงกันมาก่อนมีผลเหนือขั้นอัตโนมัติเหล่านั้น
- มีงานจากคนอื่นค้างอยู่มาก ให้ดู `git status` และ stage เฉพาะไฟล์ของงานที่สั่งเซฟ อย่าใช้ `git add -A` ทั้ง workspace โดยเฉพาะ `assets/fx/var-frost/sword_c.fx.json` ไม่ใช่งานของแชทนี้
- ห้ามประกาศว่าผู้ใช้รับทั้งหมดเพียงเพราะพิมพ์ OK เพื่อเปลี่ยนหัวข้อ และห้ามตีความคำขออัปเดต handoff ว่าอนุญาต commit/push
