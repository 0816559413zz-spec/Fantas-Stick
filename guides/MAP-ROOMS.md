# กฎการทำแผนที่แบบ "ห้องเป็นชิ้น" (Room pieces)

> 2026-11-21: ห้องจะย้ายไปเป็นห้อง prefab ใน Map Builder (`guides/MAP-STANDARD.md` §3 รอบ 3) — กฎนี้ใช้กับห้องในโค้ดจนกว่าจะย้ายเสร็จ

ผู้ใช้ตั้งกฎนี้เมื่อ 2026-11-20: ทุกห้องหรือลานในแผนที่ต้องเป็นชิ้นแยกกัน จะได้เปลี่ยนสไตล์ ย้าย หรือเปลี่ยนรูปแบบทีละห้องได้ แล้วยกไปวางทับหรือต่อเข้ากับห้องอื่นได้เลย ตอนนี้ใช้กับแผนที่ First Castle Strike (`fcs`) และแผนที่ใหม่ที่เป็นปราสาท/อาคารควรทำตามกฎเดียวกัน

## กฎ

1. **หนึ่งห้อง = หนึ่งไฟล์** `js/02-room-<id>.js` ไฟล์นั้นเรียก `fcsRoomAdd({...})` ครั้งเดียว และต้องเพิ่มชื่อไฟล์ใน `FILES` (`index.html`) หลัง `02-fcs-rooms` และก่อน `02-fcs`
2. **ห้องเป็นเจ้าของกรอบของตัวเอง** `rect:[x0,y0,x1,y1]` นับเป็นช่องของ Map Editor (รวมผนังของห้องเอง) สิ่งที่อยู่ในกรอบจัดการแบบนี้:
   - กำแพงจาก Map Editor ถูกตัดทิ้ง
   - ลัง เสา และต้นไม้ถูกตัดทิ้ง
   - แกน จุดเกิด กำแพงพังได้ และประตูของโหมดยังอยู่
   - กรอบของห้องห้ามทับกัน
3. **ใช้พิกัดภายในห้องเสมอ** ตำแหน่งทุกอย่างเป็น `u,v` (px) นับจากมุมซ้ายบนของกรอบ (u = ไปทางตะวันออก, v = ไปทางใต้) ใช้ helper เหล่านี้:
   - `roomWall` กำแพง
   - `roomCol` เสาหรือสิ่งกีดขวาง
   - `roomFloor` พื้นที่เดินได้
   - `roomCeil` เพดาน
   - ในส่วนภาพใช้ `K.X(u)` และ `K.Y(v)`

   ผลคือย้าย `rect` แล้วทั้งห้องย้ายตามไปด้วย ต้องย้ายเป็นจำนวนเต็มช่อง เพื่อให้พื้นยังตรงกับตารางพื้น 45 px
4. **ประตูคือจุดต่อ** ระบุใน `doors:[{side,at,w,kind}]`:
   - `side` คือ N/S/E/W
   - `at` คือตำแหน่งกลางประตูตามแนวผนัง (px ภายในห้อง)
   - `w` คือความกว้าง
   - `kind` เป็น `door` / `bw` (ช่องกำแพงพังได้) / `open`

   ห้องที่อยู่ติดกันต้องมีประตูตรงกัน ก่อนเปลี่ยนห้องใดห้องหนึ่ง ให้เช็กประตูของห้องข้าง ๆ ด้วย
5. **แยกการเล่นออกจากหน้าตา**
   - `gen(K)` คือส่วนการเล่น (ที่ชน พื้น เพดาน) ทำงานบนทุกเครื่องและต้องได้ผลเหมือนกันทุกเครื่อง ห้ามสุ่มโดยไม่มี seed คงที่ แก้ `gen` เมื่อไรต้องเพิ่ม `PREFIX` ใน `js/10-net.js`
   - `view(K,V)` คือหน้าตาอย่างเดียว (`V.box/cyl/cone/roof/light/chandelier` รวมเป็นก้อนตามวัสดุใน `fcsRoomsView`, js/28-fcs-castle.js) เปลี่ยนสไตล์ห้องได้โดยแก้แค่ `view` และไม่ต้องเพิ่ม PREFIX
6. **ห้องมีหลังคาต้องสูงพอให้ตัวที่บินได้เล่นได้** เพดานต้องสูงอย่างน้อย 20 ม. (`roomCeil`) ระบบจะกดผู้เล่น ตัวที่บิน และกล้องไว้ใต้เพดานเอง (`fcsCeilAt` → `cityCeilH` / `fcsCeilClamp` / `camObsK`) ใต้ชั้นลอยให้ใส่ `roomCeil` ระดับต่ำพร้อม `zmax`
7. **กล้อง** `camObsK` (js/31-camera.js) ดึงกล้องเข้าหาตัวก่อนจะชนผนัง เสา หรือเพดาน สิ่งกีดขวางที่ควรบังกล้องต้องมีรัศมีอย่างน้อย 14 px ของบาง ๆ เช่น ราวกันตกหรือรั้ว ให้ใช้รัศมีต่ำกว่านั้น
8. **ตรวจทุกครั้งที่ทำหรือแก้ห้อง** (headless ดูตัวอย่างใน CHANGELOG 2026-11-20):
   - เดินขึ้นบันไดได้
   - กระโดดหรือบินแล้วติดเพดาน
   - กล้องไม่เข้าไปในผนัง
   - ถ่ายภาพทั้งในและนอกห้อง
   - เพิ่มรายการรอรีวิว

## ของในห้องและการพัง (ผู้ใช้สั่ง 2026-11-20)

- **ของตกแต่ง** (โต๊ะ ลัง ถัง เก้าอี้ ชั้นหนังสือ ฯลฯ) ใส่ด้วย `roomProp(K,kind,u,v,{L,a,z0})` ชนิดของและค่าต่าง ๆ อยู่ใน `RPK` (js/02-fcs-rooms.js) ทุกชิ้นเป็นกลุ่ม BRK ซึ่ง snapshot `BK` ส่งสถานะให้ทุกเครื่องอยู่แล้ว โดนสกิลแรงจนพังแล้ว ของจะแตกสลายเหลือเศษกระจายที่ชนไม่ได้ (`rub:0`)
- **ราวกันตก** พังแล้วเหลือกองซากเตี้ย ๆ ที่ชนไม่ได้ ตรงนั้นกลายเป็นช่องให้กระโดดลง
- **เสาใหญ่** แตกเฉพาะผิวเป็นขั้น มีเศษหลุดตก แต่เสาไม่ล้มและยังบังได้ (`rub:1`)
- **ผนังห้อง** ไม่พัง โดนสกิลแล้วมีเศษหินกระเด็นและเกิดรอยร้าวหรือรอยไหม้ค้างอยู่ (event `rwh`, `roomWallEnv` → `fcsWallHit`)
- **ห้องต้องมีของตกแต่งเยอะ** ให้ดูเหมือนมีคนเคยอยู่จริง หน้าตาของแต่ละชนิดสร้างใน `frpBuild` (js/28-fcs-props.js) ของทุกห้องรวมเป็นก้อนเดียว (draw call เดียว) ส่วนเศษเป็น InstancedMesh รวม 2400 ชิ้น
- ของที่ชนไม่ได้ (`col:0`) ยังพังได้ ส่วนสิ่งกีดขวางลอยตัว (`bot>2`) บอทจะไม่ถือว่าขวางทางบนพื้น
