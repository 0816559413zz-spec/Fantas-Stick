# Map Editor — รูปแบบไฟล์แผนที่ (`maps/<id>.json`)

Tool: `mapedit.html` (ศูนย์รวม Tool → Map Editor) • โค้ด: `mapedit/editor.js` • เซิร์ฟเวอร์: `tools/serve.py` (`/api/maps`, `/api/map`, `/api/map-del`, `/api/map-img`)

แผนที่เป็น **ภาพอ้างอิงมุมบน (topdown) สำหรับคุยออกแบบ** ไม่ใช่ข้อมูลที่เกมโหลด (ยัง) — ถ้าวันหนึ่งทำ 3D Map Editor ให้ใช้ไฟล์นี้เป็นต้นทาง

## Claude อ่านอะไร
1. `maps/MAPS.md` — รายชื่อแผนที่ทั้งหมด
2. `maps/<id>.md` — สรุปที่อ่านง่าย: ข้อมูลพื้นฐาน, คำอธิบายผู้ใช้, ตารางโซน/ของ/Interact/เส้นทาง/โน้ต, ผลตรวจทางเดิน, กริด ASCII ความสูง + ผัง
3. `maps/<id>.png` — ภาพ topdown (เปิดด้วย Read) มีเลขพิกัดทุก 5 ช่องที่ขอบ
4. `maps/<id>.json` — ข้อมูลดิบ (ด้านล่าง) ถ้าต้องการรายละเอียดระดับช่อง

ทั้ง 3 ไฟล์เขียนใหม่ทุกครั้งที่ผู้ใช้บันทึก (บันทึกอัตโนมัติหลังหยุดแก้ 2.5 วิ หรือ Ctrl+S). `.md`/`.png` สร้างจากฝั่งเบราว์เซอร์ — ถ้า Claude แก้ `.json` เอง ต้องเปิด/บันทึกใน Map Editor อีกครั้งเพื่อให้ `.md`/`.png` ตรง

## พิกัด
- `x` = คอลัมน์ ซ้าย→ขวา, `y` = แถว บน→ล่าง, ด้านบน = เหนือ. กริดเก็บเป็น `grid[y][x]`
- 1 ช่อง = `cell` เมตร, ความสูง 1 ระดับ = `lvl` เมตร
- ของ/โซน: `x,y` = มุมซ้ายบน (ช่อง), `w,h` = กว้าง×ยาว (ช่อง). เส้นทาง/โน้ต: พิกัดทศนิยม (กลางช่อง = `x+0.5`)
- `rot` (องศา) 0 = หันขึ้น/เหนือ, 90 = ขวา

## ฟิลด์
| ฟิลด์ | ความหมาย |
|---|---|
| `v` | เวอร์ชันรูปแบบ (1) |
| `id`, `name`, `desc` | id ไฟล์ (a-z 0-9 _ -), ชื่อ, คำอธิบายจากผู้ใช้ |
| `w`, `h`, `cell`, `lvl` | ขนาดกริด, เมตรต่อช่อง, เมตรต่อระดับ |
| `rules` | `{up, down, speed, diag}` กฎที่ใช้ตรวจทางเดิน: ขึ้นต่างระดับได้เอง `up` ระดับ, ลงได้ `down` ระดับ, ความเร็ว ม./วิ, เดินทแยงได้ไหม |
| `height[y][x]` | ระดับพื้น จำนวนเต็ม -5..15 |
| `surf[y][x]` | พื้นผิว (index): 0 ดิน, 1 หญ้า, 2 หิน/พื้นปราสาท, 3 ไม้, 4 ทราย (×1.2 ช้า), 5 โคลน (×1.6), 6 น้ำตื้น (×1.5), 7 น้ำลึก (เดินไม่ได้), 8 น้ำแข็ง, 9 ลาวา (เดินไม่ได้), 10 หลุม/เหว (เดินไม่ได้), 11 พุ่มสูง |
| `wall[y][x]` | 0 ไม่มี, 1 กำแพงทึบ, 2 กำแพงเตี้ย/ที่กำบัง, 3 รั้ว/ราว (มองทะลุ) — ทุกแบบเดินผ่านไม่ได้ |
| `walk[y][x]` | บังคับ: 0 อัตโนมัติ, 1 เดินได้, 2 ห้ามเดิน (ทับทุกอย่าง) |
| `ramp[y][x]` | ทางลาด: 0 ไม่มี, 1 ขึ้นไปทางเหนือ, 2 ตะวันออก, 3 ใต้, 4 ตะวันตก. ช่องลาดสูง h เชื่อมช่องด้านหน้า (ทิศที่ขึ้น) ที่สูง h+1 |
| `objs[]` | `{id, t, x, y, w, h, rot, lb, note, foot, lv?, el?, ia?, links?}` |
| `zones[]` | `{id, name, x, y, w, h, col, note, kind?}` — `kind`: `"phase"` = พื้นที่เล่นของเฟส (ชื่อเดียวกันหลายกรอบ = เฟสนั้นเล่นหลายพื้นที่รวมกัน), ไม่ใส่/`"theme"` = ธีม/คำอธิบายพื้นที่ (ซ้อนทับเฟสได้ ไม่ใช่ข้อผิดพลาด) |
| `routes[]` | `{id, name, kind, pts:[[x,y]…], note?}` — kind: `main` ทางหลัก, `flank` ทางอ้อม, `secret` ทางลับ, `retreat` ทางถอย, `other` |
| `notes[]` | `{id, x, y, text}` |
| `ref` | ภาพอ้างอิงใต้แผนที่ `{src, x, y, wc (กว้างกี่ช่อง), op}` (ไฟล์อยู่ `maps/img/`) |
| `seq` | ตัวนับ id ภายใน |

### ของ (`objs[].t`)
- ระบบเกม: `spawnA` จุดเกิดฝ่ายบุก, `spawnB` ฝ่ายรับ, `core` แกน, `point` จุดยึด/ธง, `pickup`, `view` จุดมอง
- สิ่งก่อสร้าง: `pillar`, `crate`, `tree`, `bush`, `rock`, `building`, `tower`, `bridge`, `torch`, `statue`, `deco`
- Interact: `breakwall` กำแพงพังได้, `gate`, `lever`, `plate`, `drawbridge`, `lift`, `jumppad`, `portal`, `barrel`, `climb`, `elem` แหล่งธาตุ, `trap`, `custom`
- `foot` = ผลต่อทางเดินของพื้นที่ใต้ของ: `none` ตามพื้น, `block` ขวาง, `pass` เดินได้ (เช่นสะพาน; ถ้ามี `lv` = ระดับพื้นบนสะพาน)
- `el` = ธาตุ (Fire/Water/Wind/Earth/Frost/Storm/Nature)

### Interact (`objs[].ia`)
`{kind, by, hp, res, reset, post}`
- `kind`: `break` พังได้, `open` เปิด/ปิด, `activate` กดใช้งาน, `launch` ดีดตัวไปเป้า, `warp` วาร์ปไปเป้า, `lift` ลิฟต์ (สองทาง), `climb`, `push`, `burn`, `freeze`, `other`
- `by` ทำได้ด้วยอะไร (ข้อความ), `hp` ความทน/เวลา, `res` ผลลัพธ์, `reset` คืนสภาพ
- `post` = ผลต่อทางเดิน **หลัง** interact (`none/block/pass`); ก่อน = `foot`
- `links` = id ของที่เชื่อม (คันโยก → ประตู). `launch`/`warp`/`lift` สร้างทางเดินไปเป้าในการตรวจทางเดินด้วย

## การตรวจทางเดิน (ใน Tool และใน `.md`)
ช่องเดินไม่ได้ = พื้นผิวที่เดินไม่ได้ / มีกำแพง / ของที่ `block` / `walk=2` (ยกเว้น `walk=1` หรือของ `pass`).
ก้าวไปช่องข้างๆ ได้เมื่อ ระดับเท่ากัน, หรือขึ้น ≤ `rules.up`, หรือลง ≤ `rules.down`, หรือผ่านทางลาดตามทิศ. ทแยงได้เฉพาะพื้นเรียบที่ 2 ช่องข้างก็เดินได้.
**ทางลาด = ช่องที่ระดับ h + ลูกศรชี้ไปช่องที่ระดับ h+1 พอดี** (ลูกศรไม่ได้ทำให้พื้นสูงขึ้น ต้องมีระดับต่างกัน 1 ก่อน). ลูกศรที่ชี้ไปช่องระดับเท่ากัน/ต่ำกว่า/ต่างเกิน 1 = ใช้ไม่ได้ (Tool ขึ้นสีแดง + เตือนใน `.md`). ขึ้นสูง N ระดับ = ต้องไล่ระดับ 0,1,2,… N-1 ทีละช่อง ทุกช่องมีลูกศรชี้ต่อกัน (Tool: โหมด "⟋ บันได" ลากทีเดียวทำให้).
ตรวจ 2 สถานะ: **ก่อน Interact** และ **หลัง Interact** (ใช้ `ia.post`) — รายงานพื้นที่ที่ไปไม่ถึงจากจุดเกิด และระยะเดินจริงจากจุดเกิด → แกน/จุดยึด

## ข้อจำกัด
- กริด 2D + ความสูง: ทำพื้นซ้อนชั้น (ทางลอดใต้สะพาน) ไม่ได้ — สะพาน `pass` + `lv` จะทับช่องข้างล่าง
- ไม่มีเพดาน/หลังคา — เขียนในโน้ต
