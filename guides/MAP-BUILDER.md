# Map Builder — ทำแผนที่จริงแล้วส่งเข้าเกม (`mapbuild.html`)

Tool: ศูนย์รวม Tool → **Map Builder** • โค้ด: `mapbuild/app.js` (หน้าจอ 3D + เครื่องมือ + ส่งออก .glb) + `mapbuild/model.js` (ข้อมูล + แปลงเป็นข้อมูลเกม + ตัวตรวจ — ไม่พึ่ง three.js รันใน node ได้) • เซิร์ฟเวอร์: `tools/serve.py` (`/api/mb*`)

ต่างจาก **Map Editor (ผังร่าง)** `mapedit.html` ที่เป็นภาพอ้างอิงสำหรับคุยออกแบบ: Map Builder ทำ **แผนที่ที่เกมโหลดได้จริง** ใช้ท่อเดียวกับแผนที่จาก Blender (`guides/MAP-DESIGN.md`) — เกมไม่ต้องรู้ว่าแผนที่มาจากไหน

## ไฟล์
| ไฟล์ | คืออะไร |
|---|---|
| `maps/build/<id>.json` | **ต้นฉบับ** ที่ Editor เปิด/บันทึก (บันทึกอัตโนมัติ 4 วิหลังแก้ หรือ Ctrl+S) |
| `assets/maps/<id>.json` + `.glb` | สิ่งที่เกมโหลด — เขียนเมื่อกด **⬆ ส่งเข้าเกม** (รูปแบบเดียวกับ `assets/src/maps/map_export.py`, มี `"mb":1`) |
| `assets/manifest.json` → `maps.<id>` | เพิ่ม/ขยับเลข `v` อัตโนมัติทุกครั้งที่ส่ง |
| `assets/mapkit/kit.json` | คลัง Asset (`assets` = สร้างด้วย `node tools/mapkit-gen.js` จากชิ้นใน `assets/maps/*.glb`, `user` = ที่ผู้ใช้เพิ่มเอง ไฟล์อยู่ `assets/mapkit/*.glb`) |

- เซิร์ฟเวอร์ไม่ยอมให้ id ซ้ำกับแผนที่ที่ไม่มีต้นฉบับใน `maps/build/` (กันเขียนทับแผนที่ Blender)
- **▶ ทดลองเล่น** = ส่งเข้าเกม แล้วเปิด `index.html?nosw&playmap=<id>` (เกมข้ามหน้าเปิด เริ่มห้องฝึกบนแผนที่นั้นทันที; `&pm=ffa|coop|…` เลือกโหมด) — โค้ดฝั่งเกม: `PLAYMAP` (js/02-data, js/11-host `hostStart`, js/39-menu, js/40)
- ลบ/ถอดออกจากเกม: `POST /api/mb-unexport?id=` (ลบไฟล์ใน assets/maps + manifest) • `POST /api/mb-del?id=` (ถอด + ย้ายต้นฉบับไป `maps/build/_deleted/`) — ยังไม่มีปุ่มในหน้า

## หน่วยและพิกัด
- 1 หน่วย = 1 เมตรในโลก 3D = 20 px ของเกม • `x` = ตะวันออก (0..W), `z` = ใต้ (0..H), `y` = สูง • เหนือ = −z (ด้านบนของมินิแมพ)
- ในเกม: `X = x*20`, `Y = z*20`; โลก 3D ของเกมมีกลางแผนที่เป็น (0,0,0) → .glb มีกลุ่ม `mb_root` เลื่อน (−W/2, 0, −H/2)
- `rot` = หมุนรอบแกนตั้ง (เรเดียน, เท่ากับ `rotation.y` ของ three.js) • จุดเกิดหันไปทาง +z เมื่อ `rot = 0`

## ต้นฉบับ `maps/build/<id>.json`
| ฟิลด์ | ความหมาย |
|---|---|
| `v`, `id`, `name`, `desc` | เวอร์ชัน (1), id ไฟล์, ชื่อ/คำอธิบายที่โชว์ในล็อบบี้ |
| `W`, `H` | ขนาด (ม.) • ตารางพื้น `nx = W/0.5+1`, `ny = H/0.5+1` (ช่อง 0.5 ม. = ตารางชนของเกมพอดี → เห็นอย่างไรชนอย่างนั้น) |
| `hg` | ความสูงพื้น int16 หน่วย ซม. เข้ารหัส base64 (เรียง `j*nx+i`) |
| `sf` | พื้นผิวต่อจุด uint8 base64 = index ใน `SURF` (`model.js`) — `mud/water/ice/lava` ถูกส่งเป็น `env` ของเกมด้วย |
| `sky`, `fog [สี,เริ่ม,สุด]`, `music`, `weather`, `fx[]`, `modes[]`, `random`, `autoProps`, `skirt` | ค่าของแผนที่ (ความหมายตาม MAP-DESIGN §3) • `skirt` = พื้นยื่นเลยขอบเล่น (ม.) กันเห็นขอบลอย |
| `walls[]` | `{id, pts:[[x,z]…], th, h, c, m, closed, curve, brk, base}` — `curve` = โค้งผ่านจุด (Catmull-Rom) • `brk` = พังได้ แตกเป็นช่วงละ ~4 ม. • `base` = ความสูงฐานแบบตายตัว (กำแพง/ราวบนชั้นบน; `null` = ตั้งตามพื้น) • `m` = วัสดุตอนพัง `stone/wood/ice` |
| `floors[]` | พื้นชั้นบน `{id, x, z, w, d, rot, y, y2, th, c, steps}` — สี่เหลี่ยมหมุนได้ ผิวบนสูง `y` ที่ปลาย −d และ `y2` ที่ปลาย +d (ต่างกัน = ทางลาด) • `steps` = หน้าตาเป็นขั้นบันได (การชนยังเป็นทางลาดเรียบ) |
| `objs[]` | `{id, t, x, z, y, rot, …}` — `y` = ยกจากพื้น |
| `seq` | ตัวนับ id |

### ชนิดของ (`objs[].t`)
- จุดเกม: `spawn` (ทั่วไป), `spawnR`/`spawnB` (ทีมแดง/น้ำเงิน), `espawn` (มอนสเตอร์ Co-op), `ring` (ห่วงแข่ง, `y` = ความสูงห่วง), `task` (ภารกิจ), `light` (`c, int, dist`, `y` = สูงจากพื้น)
- ของในเกม (เกมใส่โมเดล/ระบบพังเอง): `pcrate`, `pbarrel`, `pchest`, `ptree`, `ppine`, `house` (`sx, sz` = เท่าของขนาดมาตรฐาน 8×6.5)
- ทรงพื้นฐาน: `box`, `cyl`, `cone`, `ball`, `wedge` (`sx, sy, sz` = ขนาดเป็นเมตร, `c` สี, `glow` เรืองแสง)
- จากคลัง: `kit:<id ใน kit.json>` (`s` = ขนาดเป็นเท่า)
- ของที่มองเห็น (ทรงพื้นฐาน + คลัง) ปรับได้: `col` (0/1 ชนไหม), `cs` (ขนาดที่ชนเป็นเท่าของรูปทรง — ต้นไม้ตั้งต้น 0.22 = แค่ลำต้น), `brk` (0/1 พังได้)

## สิ่งที่ส่งเข้าเกม
- **พื้น** → `g` (ตาราง 0.5 ม.) + mesh `ground` สีจุดยอด (เกมใส่รอยสนามรบ `grLive`, ผิววัสดุ `js/76`, และปลูกหญ้า 3D บนส่วนที่เขียว `js/50`) — แผนที่ที่มีจุดเกิน 70,000 จุด mesh พื้นจะหยาบลงเป็น 1 ม.
- **พื้นชั้นบน** → `fl[]` (ตาราง `top/bot`) — เดินลอดได้เมื่อช่องว่าง ≥ 2.8, ก้าวขึ้นขอบได้ ≤ 1.1
- **กำแพง/ของ** → `obs[]` วงกลมเรียงต่อกัน (เกมรู้จักแต่วงกลม) รัศมี = ครึ่งความหนา (ขั้นต่ำ 0.25) → กำแพงยิ่งบางยิ่งใช้วงเยอะ (ตัวตรวจเตือนที่ 1,200 / ห้ามเกิน 2,000)
  - ของที่ลอย/ตั้งบนชั้นบน ได้ `bot` (วงชนเริ่มสูงจากพื้นเท่านี้ → ไม่ขวางคนข้างล่าง; `regFileMap` js/02-data ส่งต่อให้แล้ว)
  - พังได้ → `brk[]` + `userData.brk` บนชิ้นใน .glb (ระบบของบังพังได้ js/12 `genBrk`, js/23 `brkSetup`)
- **หน้าตา** → `.glb`: `ground`, กำแพง/ชั้นบนรวมเป็นชิ้นตามสี (`mb_static_*`), ของจากคลัง/ทรงพื้นฐาน, ชิ้นพังได้แยกชิ้น • วัสดุชื่อขึ้นต้น `glow_`/`ice_` = เกมไม่ใส่ผิววัสดุทับ
- ยังไม่บีบอัด (ไม่มี Draco): แผนที่ 90×60 ≈ 1 MB

## ตัวตรวจ (แผงขวา "ตรวจก่อนส่งเข้าเกม", `model.js check`)
จุดเกิดครบไหม/อยู่บนทางชัน/ชิดที่ชน/เดินถึงกันไหม (ตรวจคร่าว ๆ ที่ระดับพื้น ช่อง 1 ม.), จำนวนวงชน, ไฟเกิน 12, ระดับพื้นเกิน −5..+20, ใต้ชั้นบนเตี้ยกว่า 2.8, จุดของโหมดเฉพาะ (ห่วง/ภารกิจ)

## ข้อจำกัดตอนนี้
- **โหมดบุกปราสาท (`siege`) ยังใช้แผนที่จาก Map Builder ไม่ได้** — โหมดนั้นอ่านข้อมูลกริดของตัวเอง (`js/02-fcs*.js` จาก `mapedit.html`) ต้องต่อระบบแกน/เฟส/ประตูเพิ่ม
- ทางลอดใต้ดิน/ถ้ำ: ทำเป็นพื้นชั้นบนเป็นหลังคา (พื้นหลักมีชั้นเดียว)
- พื้นผิวพิเศษ (น้ำ/น้ำแข็ง/ลาวา/โคลน) ตอนนี้เป็นสีบนพื้น + ข้อมูล `env` — ผลกับการเล่นรอระบบเฟส 2 ของเกม (MAP-DESIGN §8)
- ของจากคลังใช้ภาพผิวของแผนที่ต้นทาง → ใช้ของจากหลายแผนที่ = หลายวัสดุ (draw call เพิ่ม)

## Claude แก้แผนที่เอง
แก้ `maps/build/<id>.json` ได้ตรง ๆ (ยกเว้น `hg`/`sf` ที่เป็น base64 — ใช้ `mapbuild/model.js`: `unpack` → แก้ `M.hg[j*nx+i]` → `pack`) แล้วเปิด Map Builder กด **⬆ ส่งเข้าเกม** (ต้องใช้เบราว์เซอร์สร้าง .glb) หรือสั่งจากคอนโซลของหน้า: `await __mb.exportGame()`
