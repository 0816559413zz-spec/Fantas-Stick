# Map Builder — ทำแผนที่จริงแล้วส่งเข้าเกม (`mapbuild.html`)

Tool: ศูนย์รวม Tool → **Map Builder** • โค้ด: `mapbuild/app.js` (หน้าจอ 3D + เครื่องมือ + ส่งออก .glb) + `mapbuild/model.js` (ข้อมูล + แปลงเป็นข้อมูลเกม + ตัวตรวจ — ไม่พึ่ง three.js รันใน node ได้) • เซิร์ฟเวอร์: `tools/serve.py` (`/api/mb*`)

ต่างจาก **Map Editor (ผังร่าง)** `mapedit.html` ที่เป็นภาพอ้างอิงสำหรับคุยออกแบบ: Map Builder ทำ **แผนที่ที่เกมโหลดได้จริง** ใช้ท่อเดียวกับแผนที่จาก Blender (`guides/MAP-DESIGN.md`) — เกมไม่ต้องรู้ว่าแผนที่มาจากไหน

> **มาตรฐาน:** แผนที่ทุกอันทำใน Map Builder — กฎ + แผนย้าย fcs อยู่ `guides/MAP-STANDARD.md`

## ไฟล์
| ไฟล์ | คืออะไร |
|---|---|
| `maps/build/<id>.json` | **ต้นฉบับ** ที่ Editor เปิด/บันทึก (บันทึกอัตโนมัติ 4 วิหลังแก้ หรือ Ctrl+S) |
| `assets/maps/<id>.json` + `.glb` | สิ่งที่เกมโหลด — เขียนเมื่อกด **⬆ ส่งเข้าเกม** (รูปแบบเดียวกับ `assets/src/maps/map_export.py`, มี `"mb":1`) |
| `assets/manifest.json` → `maps.<id>` | เพิ่ม/ขยับเลข `v` อัตโนมัติทุกครั้งที่ส่ง |
| `assets/mapkit/kit.json` | คลัง Asset (`assets` = สร้างด้วย `node tools/mapkit-gen.js` จากชิ้นใน `assets/maps/*.glb`, `user` = ที่ผู้ใช้เพิ่มเอง ไฟล์อยู่ `assets/mapkit/*.glb`) |

- เซิร์ฟเวอร์ไม่ยอมให้ id ซ้ำกับแผนที่ที่ไม่มีต้นฉบับใน `maps/build/` (กันเขียนทับแผนที่ Blender)
- **▶ ทดลองเล่น** = ส่งเข้าเกม แล้วเปิด `index.html?nosw&playmap=<id>` (เกมข้ามหน้าเปิด เริ่มห้องฝึกบนแผนที่นั้นทันที; `&pm=ffa|coop|…` เลือกโหมด) — โค้ดฝั่งเกม: `PLAYMAP` (js/02-data, js/11-host `hostStart`, js/39-menu, js/40)
- ลบ/ถอดออกจากเกม: `POST /api/mb-unexport?id=` (ลบไฟล์ใน assets/maps + manifest) • `POST /api/mb-del?id=` (ถอด + ย้ายต้นฉบับไป `maps/build/_deleted/`) — ยังไม่มีปุ่มในหน้า

## หน่วยและพิกัด
- 1 หน่วย = 1 เมตรในโลก 3D = 20 px ของเกม • `x` = ตะวันออก (0..W), `z` = ใต้ (0..H), `y` = สูง • เหนือ = −z (ด้านบนของมินิแมพ)
- ในเกม: `X = x*20`, `Y = z*20`; โลก 3D ของเกมมีกลางแผนที่เป็น (0,0,0) → .glb มีกลุ่ม `mb_root` เลื่อน (−W/2, 0, −H/2)
- `rot` = หมุนรอบแกนตั้ง (เรเดียน, เท่ากับ `rotation.y` ของ three.js) • จุดเกิดหันไปทาง +z เมื่อ `rot = 0`

## ต้นฉบับ `maps/build/<id>.json`
| ฟิลด์ | ความหมาย |
|---|---|
| `v`, `id`, `name`, `desc` | เวอร์ชัน (1), id ไฟล์, ชื่อ/คำอธิบายที่โชว์ในล็อบบี้ |
| `W`, `H` | ขนาด (ม.) • ตารางพื้น `nx = W/0.5+1`, `ny = H/0.5+1` (ช่อง 0.5 ม. = ตารางชนของเกมพอดี → เห็นอย่างไรชนอย่างนั้น) |
| `hg` | ความสูงพื้น int16 หน่วย ซม. เข้ารหัส base64 (เรียง `j*nx+i`) |
| `sf` | พื้นผิวต่อจุด uint8 base64 = index ใน `SURF` (`model.js`) — `mud/water/ice/lava` ถูกส่งเป็น `env` ของเกมด้วย |
| `look`, `lt` | (ไม่บังคับ แก้ไฟล์ตรง ๆ — ยังไม่มีช่องใน Editor) `look` = ชื่อพรีเซ็ต Look (js/74-look.js เช่น `gorge`) • `lt` = `{hemi:[ฟ้า,พื้น,แรง], sun:[สี,แรง,[x,y,z]], sky:'#สี' ฟ้าครึ้มสีเดียว, exp}` แสง/ฟ้าเฉพาะแมพ (js/28 `buildFileMap`) — ตัวอย่าง `maps/build/gorge.json` |
| `sky`, `fog [สี,เริ่ม,สุด]`, `music`, `weather`, `fx[]`, `modes[]`, `random`, `autoProps`, `skirt` | ค่าของแผนที่ (ความหมายตาม MAP-DESIGN §3) • `skirt` = พื้นยื่นเลยขอบเล่น (ม.) กันเห็นขอบลอย |
| `walls[]` | `{id, pts:[[x,z]…], th, h, c, m, closed, curve, brk, base}` — `curve` = โค้งผ่านจุด (Catmull-Rom) • `brk` = พังได้ แตกเป็นช่วงละ ~4 ม. • `base` = ความสูงฐานแบบตายตัว (กำแพง/ราวบนชั้นบน; `null` = ตั้งตามพื้น) • `m` = วัสดุตอนพัง `stone/wood/ice` |
| `floors[]` | พื้นชั้นบน `{id, x, z, w, d, rot, y, y2, th, c, steps}` — สี่เหลี่ยมหมุนได้ ผิวบนสูง `y` ที่ปลาย −d และ `y2` ที่ปลาย +d (ต่างกัน = ทางลาด) • `steps` = หน้าตาเป็นขั้นบันได (การชนยังเป็นทางลาดเรียบ) |
| `objs[]` | `{id, t, x, z, y, rot, …}` — `y` = ยกจากพื้น |
| `parts[]` | ชิ้นส่วนปราสาท (หัวข้อ "ชิ้นส่วนปราสาท" ด้านล่าง) |
| `seq` | ตัวนับ id |

### ชนิดของ (`objs[].t`)
- จุดเกม: `spawn` (ทั่วไป), `spawnR`/`spawnB` (ทีมแดง/น้ำเงิน), `espawn` (มอนสเตอร์ Co-op), `ring` (ห่วงแข่ง, `y` = ความสูงห่วง), `task` (ภารกิจ), `light` (`c, int, dist`, `y` = สูงจากพื้น)
- ของในเกม (เกมใส่โมเดล/ระบบพังเอง): `pcrate`, `pbarrel`, `pchest`, `ptree`, `ppine`, `house` (`sx, sz` = เท่าของขนาดมาตรฐาน 8×6.5)
- ทรงพื้นฐาน: `box`, `cyl`, `cone`, `ball`, `wedge` (`sx, sy, sz` = ขนาดเป็นเมตร, `c` สี, `glow` เรืองแสง)
- จากคลัง: `kit:<id ใน kit.json>` (`s` = ขนาดเป็นเท่า)
- ของที่มองเห็น (ทรงพื้นฐาน + คลัง) ปรับได้: `col` (0/1 ชนไหม), `cs` (ขนาดที่ชนเป็นเท่าของรูปทรง — ต้นไม้ตั้งต้น 0.22 = แค่ลำต้น), `brk` (0/1 พังได้)
- ของในเกม (`house`, `pcrate`, `pbarrel`, `ptree`, `ppine`): `brk: 0` = พังไม่ได้ (ช่อง "พังได้" ในแผงขวา, ค่าเริ่ม = พังได้) → ส่งเข้าเกมเป็น `houses[].nb` / `props[].nb` (js/12 `hitBldPiece`, js/11 `hitProp` ข้าม)

## สิ่งที่ส่งเข้าเกม
- **พื้น** → `g` (ตาราง 0.5 ม.) + mesh `ground` สีจุดยอด (เกมใส่รอยสนามรบ `grLive`, ผิววัสดุ `js/76`, และปลูกหญ้า 3D บนส่วนที่เขียว `js/50`) — แผนที่ที่มีจุดเกิน 70,000 จุด mesh พื้นจะหยาบลงเป็น 1 ม.
- **พื้นชั้นบน** → `fl[]` (ตาราง `top/bot`) — เดินลอดได้เมื่อช่องว่าง ≥ 2.8, ก้าวขึ้นขอบได้ ≤ 1.1
- **กำแพง/ของ** → `obs[]` วงกลมเรียงต่อกัน (เกมรู้จักแต่วงกลม) รัศมี = ครึ่งความหนา (ขั้นต่ำ 0.25) → กำแพงยิ่งบางยิ่งใช้วงเยอะ (ตัวตรวจเตือนที่ 1,200 / ห้ามเกิน 2,000)
  - ของที่ลอย/ตั้งบนชั้นบน ได้ `bot` (วงชนเริ่มสูงจากพื้นเท่านี้ → ไม่ขวางคนข้างล่าง; `regFileMap` js/02-data ส่งต่อให้แล้ว)
  - พังได้ → `brk[]` + `userData.brk` บนชิ้นใน .glb (ระบบของบังพังได้ js/12 `genBrk`, js/23 `brkSetup`)
- **หน้าตา** → `.glb`: `ground`, กำแพง/ชั้นบนรวมเป็นชิ้นตามสี (`mb_static_*`), ของจากคลัง/ทรงพื้นฐาน, ชิ้นพังได้แยกชิ้น • วัสดุชื่อขึ้นต้น `glow_`/`ice_` = เกมไม่ใส่ผิววัสดุทับ
- ยังไม่บีบอัด (ไม่มี Draco): แผนที่ 90×60 ≈ 1 MB

## โหมดบุกปราสาท / ห้อง / ระบบ / สไตล์ (MAP-STANDARD รอบ 1, 2026-11-21)
**เกมอ่านแล้ว (รอบ 2, 2026-11-21):** `siege`, `ceil`, `sys.fence` — โหมดบุกปราสาทเล่นบนแผนที่ไฟล์ได้ครบ 3 เฟส (`sgFromFile` js/02-fcs.js ← `regFileMap` js/02-data.js) • **ยังไม่อ่าน:** `rprops` (รอบ 3 ห้อง), `sys.stonewall`/`sys.eggshell` (รอบ 3–5), `style` (รอบ 4)
- **วางของ → หมวด "โหมดบุกปราสาท"** (`OBJ` cat `mode`): `core` แกน (`n` ลำดับ 1–N, `s` ขนาด ม.) • `sgA`/`sgB` จุดเกิดฝ่ายบุก/รับ (`ph` เฟส, เฟสละ 1 จุด) • `phase` พื้นที่เล่นของเฟส (`ph`, `sx`×`sz` สี่เหลี่ยมไม่หมุน, หลายกรอบต่อเฟสได้) → ส่งออก `data.siege = {cores:[{n,x,y,s}], sp:{A:{ph:{x,y}},B:{…}}, phases:[[{x1,y1,x2,y2}]], bw:[{k,x,y,w,d,h,id}]}` (px, รูปเดียวกับ `MAPS.fcs.fcs` ใน js/02-fcs.js)
- **กำแพงเป้าหมาย**: เลือกกำแพง → "เป้าหมายบุกปราสาท" = `wall`/`gate` (`w.sg`, เปิดพังได้ให้เอง) → `siege.bw` (กรอบสี่เหลี่ยมรอบกำแพง)
- **วางของ → หมวด "ห้อง / ของพังได้"** (cat `room`): `ceil` เพดาน (`sx`×`sz`, `y` = สูงจากพื้น ค่าเริ่ม 21, `zmax` = ใช้เฉพาะคนที่เท้าต่ำกว่า → ใต้ชั้นลอย) → `data.ceil=[{x0,y0,x1,y1,h,zmax?}]` • `rp_<kind>` ของพังได้ชุด `RPK` (โต๊ะ ม้านั่ง เก้าอี้ ลัง ถัง ราว เสาใหญ่ …, `L` ความยาวสำหรับโต๊ะ/ม้านั่ง/ราว, `y` = ยกขึ้นชั้นลอย) → `data.rprops=[{k,x,y,a,L?,z0?}]` (`a` = มุมแบบเกม = −rot) • `RPK` ใน model.js ต้องตรงกับ js/02-fcs-rooms.js • ในนี้เห็นเป็นกล่อง เกมวาดหน้าตาจริงเอง (js/28-fcs-props.js)
- **ระบบ (`sys`)**: กำแพง `fence` (รั้วไหม้ได้ js/12-efs) / `stonewall` (ผนังหินมีรอยแตก/ไหม้) • พื้นชั้นบน `eggshell` (สะพานแตกแบบเปลือกไข่) → `data.sys = {fence:[[x1,y1,x2,y2,th,h]…], stonewall:[…], eggshell:[[มุม 4 จุด px]…]}`
- **สไตล์ (`style`)**: ช่อง "สไตล์หลัก" ของแผนที่ + สไตล์ต่อกำแพง/พื้นชั้นบน/ชิ้นปราสาท (`STYLE` ใน model.js) → `data.style` + ชิ้นใน .glb ได้ `userData.style` (ชิ้นที่สไตล์ต่างกันไม่รวมก้อนกัน)
- โหมด "บุกปราสาท" ในรายการโหมด: ตัวตรวจเช็กแกนเลข 1–N, ทุกเฟสมีจุดเกิดสองฝ่าย + พื้นที่เล่น, แกน/จุดเกิดอยู่ในพื้นที่ของเฟส • แผนที่ที่ติ๊กแค่บุกปราสาทไม่ต้องมีจุดเกิดทั่วไป • ▶ ทดลองเล่นแผนที่ที่ติ๊กแค่บุกปราสาท = เปิดโหมดบุกปราสาท (`&pm=siege`, เพิ่มบอทฝ่ายรับ 1 ตัว คุณเป็นฝ่ายบุก) • เลือกแผนที่บุกปราสาทในล็อบบี้ได้ (`G.mapPick`, js/11-host `sgOk`) ไม่เลือก = `fcs`
- เกมสร้างเอง (ไม่อยู่ใน .glb): กำแพง/ประตูเป้าหมาย (`siege.bw` → ที่ชน `k:'fcb'` + ภาพใน `sgViewBuild`), แกนคริสตัล, แท่นจุดเกิดสีทีม, รั้วไหม้ได้ (`sys.fence` → ที่ชน `k:'fcf'`+`fid` + ภาพ `fcsFences` ใน `sgFileBuild` js/28-fcs-build.js) • เพดาน `ceil` → `MAPS[id].ceil` (`fcsCeilAt`, กล้อง `camObsK`)
- ตัวอย่าง: `node tools/siege-sample.mjs` → `maps/build/siege-demo.json` (3 เฟส ประตู กำแพงเป้าหมาย รั้ว เพดาน) ส่งเข้าเกมแล้วเป็นแผนที่ `siege-demo` • เล่น: `index.html?nosw&playmap=siege-demo&pm=siege`
- เพดานต่ำกว่า 20 ม. ที่ไม่มี `zmax` → ตัวตรวจเตือน (MAP-ROOMS §6) • ปุ่ม "พื้นที่/เพดาน" ในแถบมุมมอง ซ่อน/แสดงกรอบ (คลิกเลือกที่เพชรกลางกรอบ)

## ห้องสำเร็จ (prefab) — MAP-STANDARD รอบ 3 (2026-11-21)
- **ห้อง = แผนที่ Map Builder ที่ id ขึ้นต้นด้วย `room-`** (`maps/build/room-<ชื่อ>.json`) พื้นราบสูง 0 วางกำแพง/ชั้นลอย/เสา/เพดาน/ของพังได้/ชิ้นปราสาทได้ตามปกติ • ความสูงในห้องนับจากพื้นห้อง • ห้องไม่ต้องส่งเข้าเกมเอง
- **วางห้องในแผนที่:** วางของ → หมวด "ห้องสำเร็จ (prefab)" → คลิก = จุดกลางห้อง • เก็บใน `M.rooms[] = {id, ref, x, z, rot}` (`rot` ทีละ 90°, Q/E) • คลิกส่วนไหนของห้องก็เลือกทั้งห้อง ลากย้ายได้ • แผงขวา: เปลี่ยนห้อง / ตำแหน่ง / หมุน / "เปิดแก้ห้องนี้"
- แก้ไฟล์ห้องครั้งเดียว → ทุกแผนที่ที่วางห้องนั้นเปลี่ยนตาม (ตอนเปิด/ส่งออกครั้งต่อไป) • ความสูงในห้อง + ความสูงพื้นแผนที่ตรงกลางห้อง
- โค้ด: `model.js` `roomExpand` / `flatRooms` / `withRooms` (ส่งออก = แผนที่ + ห้องที่แตกแล้ว ใช้ท่อเดิม) • `app.js` `loadRooms` (`/api/mb?id=room-…`), `RX` = ของในห้องที่แตกแล้ว
- **เกม:** `rprops` → ที่ชน + กลุ่มพังได้ (`roomsFromFile` js/02-fcs-rooms.js, ต่อท้าย `fm.brk`) + หน้าตาจริง (`fcsPropsBuild` js/28-fcs-props.js) • `sys.stonewall` (แนวตรงแกน X/Z) → รอยแตก/ไหม้เมื่อโดนสกิล (`roomWallEnv`) • เพดาน `ceil`
- ตัวอย่าง: `node tools/fcs-to-mb.mjs` เขียน `room-greathall` (ห้องโถงใหญ่จากโค้ด) + วางใน `fcs-draft` • `node tools/room-sample.mjs` → `room-demo` (ห้องโถงกลางทุ่ง ส่งเข้าเกมแล้ว: `index.html?nosw&playmap=room-demo`)
- ยังไม่มี: หน้าตาห้องแบบเกม (พรม ธง เตาผิง หลังคา พื้นหิน = รอบ 4 สไตล์), ประตูเป็นจุดต่อ/ดูดติดกัน, สีพื้นของห้องไม่ถูกทาลงพื้นแผนที่

## แผนที่ไฟล์เดียว + หน้าตาแบบเกม — MAP-STANDARD รอบ 4 (2026-11-21)
- **ปุ่ม "แตกห้องเข้าแผนที่"** (แผงขวาเมื่อเลือกห้อง prefab): คัดลอกของในห้องเข้าไฟล์แผนที่เป็นของปกติ แก้ได้ทุกชิ้น ไม่ผูกกับไฟล์ห้องแล้ว • พื้นใต้ห้องปรับราบเท่าพื้นห้อง + ทาสีตามห้อง (`model.js roomUnpack`) • `tools/fcs-to-mb.mjs` แตกห้องโถงใส่ `fcs-draft` ให้เลย (`--prefab` = เก็บเป็นห้องผูกไฟล์)
- **ของตกแต่งที่เกมวาด (`dc_*`, หมวด "ของตกแต่ง (เกมวาด)")**: `dc_box` / `dc_cyl` / `dc_cone` (วัสดุ `k`: หินปราสาท หินเข้ม หลังคา หน้าต่างมีไฟ ไม้ เหล็ก พรมแดง ช่องมืด พื้นหินปราสาท), `dc_roof` หลังคาจั่ว (`sx` ยาวตามสัน `sz` กว้าง `sy` สูง, หมุนได้), `dc_flame` เปลวคบ/เทียน, `dc_cloth` ผ้าแขวน (`sx`×`sy`, สี `c`), `dc_shield` โล่ประดับ, `dc_chand` โคมระย้า (มีแสงจริง) • `y` = ความสูงจุดกลางจากพื้น • ไม่มีที่ชน ไม่อยู่ใน .glb → ส่งออก `data.deco = [{t,k,x,y,h,sx,sy,sz,rt,rb,r,seg,c,a}]` → เกมวาดด้วยตัวสร้างเดียวกับห้องในโค้ด (`fcsDecoFile` / `fcsDecoKit` js/28-fcs-castle.js) • `dc_box` ไม่หมุน (หมุนห้อง 90° = สลับกว้าง/ลึก)
- **มองเห็น (`vis: 0`)**: กำแพง/พื้นชั้นบน/ทรงพื้นฐาน = ที่ชนอย่างเดียว ไม่ส่งภาพเข้า .glb (ใน Editor เห็นโปร่ง) — ใช้เมื่อของตกแต่งวาดหน้าตาแทน (ห้องโถง: ผนัง/ชั้นลอย/เสาที่ชน = `vis 0`, ภาพ = `dc_*`)
- **สไตล์ในเกม** (`fileStyleScene` js/28-fcs-castle.js): ชิ้นใน .glb ที่ `style` = `castle-stone` / `room-hall` → กำแพง/ทรง = หินก้อนปราสาท (`fcsCastleMat 's'`), พื้นชั้นบน = พื้นหินปราสาท (`'f'`) • แผนที่ `style: forest-mist` = ใช้ Look `gorge` (ถ้าไม่ได้ตั้ง `look` เอง) — ยังไม่มีหมอกเฉพาะโซนแบบป่า fcs
- `room-greathall` ตอนนี้มีหน้าตาครบจาก `view()` ของห้องในโค้ด (ผนัง ค้ำยัน หน้าต่าง ชั้นลอย บันได หอมุม หลังคา คาน โคมระย้า พรม ธง โล่ เตาผิง พื้นหิน) → ภาพเทียบ `room-demo` กับห้องโถงใน fcs แทบเหมือนกัน

## ตัวตรวจ (แผงขวา "ตรวจก่อนส่งเข้าเกม", `model.js check`)
จุดเกิดครบไหม/อยู่บนทางชัน/ชิดที่ชน/เดินถึงกันไหม (ตรวจคร่าว ๆ ที่ระดับพื้น ช่อง 1 ม.), จำนวนวงชน, ไฟเกิน 12, ระดับพื้นเกิน −5..+20, ใต้ชั้นบนเตี้ยกว่า 2.8, จุดของโหมดเฉพาะ (ห่วง/ภารกิจ)

## ชิ้นส่วนปราสาท (เครื่องมือ ♜ ปราสาท, ปุ่ม C) — `M.parts[]`
ประกอบปราสาทเองจากชิ้นสำเร็จ แก้ขนาดได้ ดูดติดกัน ใช้ท่อเดิม (ไม่มีท่อใหม่): `model.js expandParts()` แตกแต่ละชิ้นเป็น **ทรงพื้นฐาน** (box/cyl/cone/wedge → วงชน + .glb + กลุ่มพังได้) กับ **พื้นชั้นบน** (ทางเดิน/บันได/ทางลาด) แล้ว `gameData`/ส่งออกใช้ต่อได้เลย (แผงขวา "ตรวจ" นับด้วย)
- ชิ้น (`PART` ใน model.js): `wall` กำแพงตรง • `corner` กำแพงมุม L • `tower` หอคอย (กลม/เหลี่ยม, หลังคา/ยอดโล่ง) • `gate` ประตูเมือง (ช่อง กว้าง×สูง + คานเหนือช่อง + บานไม้พังได้) • `keep` ตึกใหญ่ (หอมุม, หลังคา) • `stairs` บันได • `ramp` ทางลาด • `walk` ทางเดินยก • `bridge` สะพาน (ราว + เสารอง)
- ฟิลด์: `{id,k,x,z,rot,base,c,brk}` + ขนาด (ยาว/หนา/สูง ฯลฯ) + ตัวเลือก (`bt` ฟันปลา, `wk` ทางเดินบนยอด, `door`, `round`, `roof`, `turrets`, `rail`, `piers`) • `base` = ความสูงฐานตายตัว (ว่าง = ตามพื้น) • แกนยาวของชิ้น = +z ท้องถิ่น, `rot` = หมุนรอบแกนตั้ง
- วาง: เลือกชิ้น → คลิก (กริด 0.5/1/2) • คลิกบนยอดกำแพง/ทางเดิน = วางต่อที่ความสูงนั้น • Q/E หมุน 45° (Shift = 15°) • **ดูดติด**: ปลายกำแพง/ประตู/ทางเดิน/ตัวบันได ฯลฯ ติดกันภายใน 1.6 ม. (`partPorts`/`snapPart`) — กำแพงดูดติดขอบหอ/ตึก, บันไดปลายบนดูดติดกลางกำแพงที่ความสูงเท่ากัน (ตั้ง "สูงขึ้น" = ความสูงกำแพง) • เครื่องมือเลือก: ย้าย/Q E หมุน/[ ] ย่อขยาย (ด้านหลัก)/PgUp PgDn ยก/Ctrl+D ทำซ้ำ/Del ลบ/Ctrl+Z ย้อน • แก้ขนาดละเอียดที่แผงขวา
- การชน: บล็อกใหญ่ (>3.2 ม.) ได้วงชนเป็น "วงริบ" ตามขอบ (ในกลวง เดินเข้าไม่ถึง) • ฟันปลา/พื้นบนยอดไม่มีวงชน (ยอดกำแพง = พื้นชั้นบน เดินได้ที่ความสูงยอด+0.03) • ช่องประตูลอดได้เมื่อสูง ≥ 2.2 (คานเหนือช่องมี `bot`) • ราวสะพาน/ทางเดินมีวงชนเฉพาะคนที่ยืนอยู่บนนั้น
- พังได้ (`brk`): ปิดเป็นค่าเริ่ม (= ส่งเข้าเกมแบบพังไม่ได้) • เปิด = กำแพงแตกเป็นช่วง ~4 ม. แต่จะไม่มีฟันปลา/ทางเดินบนยอด (ลอยค้างไม่ได้) • บานประตูไม้พังได้เสมอ (ตัวเลือก `door`)
- **ทรงอิสระ (`free`, ปั้นเอง/ทำ Lowpoly อ้างอิง):** เลือกชิ้น "ทรงอิสระ" แล้วคลิกวาดรูปปิดทีละจุดบนพื้น (คลิกจุดแรก/Enter/ดับเบิลคลิก = จบ, Backspace ถอย, Esc ยกเลิก) → ได้ทรงตันดึงสูง `h` + `tp` หุบยอด (1 = ตรง, 0 = แหลม) • เลือกชิ้นด้วยเครื่องมือเลือกแล้วลากจุดฟ้าปั้นรูป, Alt+คลิกที่ขอบ = เพิ่มจุด, เลือกจุด+Del = ลบจุด • ชนเฉพาะขอบรูป (ข้างในกลวง), ไม่มีพื้นเดินบนยอด, พังไม่ได้, ไม่ดูดติด
- ตัวอย่าง: `node tools/castle-sample.mjs` → `maps/build/castle-demo.json` (กำแพงรอบ 4 หอ ประตู ตึกใหญ่ บันได ทางลาด สะพาน) — ส่งเข้าเกมแล้วเป็นแผนที่ `castle-demo` (`index.html?nosw&dev=1&playmap=castle-demo`)
- ยังไม่มี: ตึกกลวง/ห้องข้างใน (ตัวตึกทึบ), ซุ้มโค้งจริง (ใช้ประตู = คานเหนือช่อง), กำแพงโค้ง/กำแพงลาดตามพื้นชัน • โหมดบุกปราสาท (`siege`) ยังอ่านแผนที่นี้ไม่ได้ (ดูข้อจำกัดด้านบน)

## ข้อจำกัดตอนนี้
- **โหมดบุกปราสาทบนแผนที่ไฟล์ (รอบ 2):** เล่นได้ แต่ยังไม่มีห้อง/ของพังได้ในห้อง/ผนังหินมีรอย/สะพานเปลือกไข่/สไตล์ (MAP-STANDARD รอบ 3–5) • ห้องและหน้าตาของ `fcs` ยังเป็นโค้ด
- ทางลอดใต้ดิน/ถ้ำ: ทำเป็นพื้นชั้นบนเป็นหลังคา (พื้นหลักมีชั้นเดียว)
- พื้นผิวพิเศษ (น้ำ/น้ำแข็ง/ลาวา/โคลน) ตอนนี้เป็นสีบนพื้น + ข้อมูล `env` — ผลกับการเล่นรอระบบเฟส 2 ของเกม (MAP-DESIGN §8)
- ของจากคลังใช้ภาพผิวของแผนที่ต้นทาง → ใช้ของจากหลายแผนที่ = หลายวัสดุ (draw call เพิ่ม)

## ร่างจากแผนที่ในเกม: fcs (`fcs-draft`)
`node tools/fcs-to-mb.mjs` → `maps/build/fcs-draft.json` แล้วเปิด `mapbuild.html?id=fcs-draft` • รัน `genFcs` ตัวเดียวกับเกม (js/02-fcs-data.js + ห้อง js/02-fcs-rooms.js + js/02-room-*.js + js/02-fcs.js) → พื้น/ความสูง, กำแพงทึบ/เตี้ย/รั้ว (`sys:fence`), กำแพงพังได้+ประตู (`sg`), ต้นสน/หิน (kit gorge), ลัง, เสา, ซากปราสาทรอบแกน 1, แกน/จุดเกิดต่อเฟส/พื้นที่เฟส (ของหมวดบุกปราสาท), สะพาน L (`sys:eggshell`), ห้อง Great Hall (ผนัง + ช่องประตู + คานเหนือประตู `sys:stonewall`, เสา, ชั้นลอย + ทางลาด, เพดาน, ของพังได้ `rp_*`) • ของจากห้องมีช่อง `room:<id>` • ไม่มี: หน้าตาปราสาท/ห้อง/ป่า/หมอกที่เขียนด้วยโค้ด (รอบ 4), กองหิน, ซุ้มโค้งสะพาน • **ไว้ดู/ดราฟเท่านั้น** — โหมดบุกปราสาทยังเล่น js/02-fcs*.js (กดส่งเข้าเกม = ได้แผนที่แยกชื่อ fcs-draft) • รันซ้ำ = เขียนทับไฟล์ร่าง (งานที่แก้ใน Builder หาย)

## สร้างแผนที่ด้วยโค้ด (ตัวอย่าง: gorge)
เขียนสคริปต์ node ที่ `import` `mapbuild/model.js` (`newMap/pack/gh/…`) สร้างภูมิประเทศ/ของ/จุดเกิดแล้วเขียน `maps/build/<id>.json` • โมเดลใหม่: เขียน .glb เอง (วัสดุเดียวสีที่จุดยอด) ใส่ `assets/mapkit/` + แถว `user` ใน `kit.json` (`node tools/gorge-assets.mjs` เป็นตัวอย่าง) • ส่งเข้าเกมไม่ต้องกดปุ่ม: `node tools/headless.js --url "mapbuild.html?export=<id>" --js tools/mb-export.js --quiet` • ถ่ายภาพ/ทดสอบ: `tools/gorge-shots.js`, `gorge-walk.js` • SURF index 16–20 (moss/litter/gravel/duff/trail) เพิ่มต่อท้ายแล้ว — ตารางต้องต่อท้ายเสมอ

## Claude แก้แผนที่เอง
แก้ `maps/build/<id>.json` ได้ตรง ๆ (ยกเว้น `hg`/`sf` ที่เป็น base64 — ใช้ `mapbuild/model.js`: `unpack` → แก้ `M.hg[j*nx+i]` → `pack`) แล้วเปิด Map Builder กด **⬆ ส่งเข้าเกม** (ต้องใช้เบราว์เซอร์สร้าง .glb) หรือสั่งจากคอนโซลของหน้า: `await __mb.exportGame()`
