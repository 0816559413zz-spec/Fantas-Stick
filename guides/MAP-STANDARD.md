# มาตรฐานการทำแผนที่ (Map Builder = มาตรฐาน)

ผู้ใช้ตัดสิน 2026-11-21: **แผนที่ทุกอันทำใน Map Builder** (`mapbuild.html`) เป็นมาตรฐานเดียว เพื่อให้แผนที่ใหม่ในอนาคตทำตามแบบเดียวกัน และเปิดมาแก้ได้ครบเหมือนในเกม
อ่านคู่กับ `guides/MAP-BUILDER.md` (รูปแบบไฟล์ + วิธีใช้ Tool), `guides/MAP-DESIGN.md` (กติกาการออกแบบ), `guides/MAP-ROOMS.md` (กฎห้องเป็นชิ้น — จะย้ายมาอยู่ใน Map Builder ตามแผนข้างล่าง)

## 1. กฎมาตรฐาน (ใช้กับแผนที่ใหม่ทุกอันตั้งแต่วันนี้)

1. **ต้นฉบับเดียว = `maps/build/<id>.json`** ทำ/แก้ใน Map Builder เท่านั้น • ห้ามเขียนแผนที่ใหม่เป็นโค้ด (`js/02-<map>.js`) • Map Editor (`mapedit.html`) = ผังร่างไว้คุยออกแบบ ไม่ใช่แผนที่จริง
2. **เกมโหลดแค่ไฟล์ที่ส่งออก** `assets/maps/<id>.json` + `.glb` ผ่าน `assets/manifest.json` (`regFileMap`, js/02-data.js) — ไม่มีโค้ดสร้างแผนที่เฉพาะอัน
3. **หน่วย/พิกัด** ตาม MAP-BUILDER.md: 1 หน่วย = 1 ม. = 20 px, x ตะวันออก, z ใต้, ตารางพื้น 0.5 ม.
4. **แผนที่ = ไฟล์เดียวที่แก้ได้ทุกจุด** (ผู้ใช้ 2026-11-21) • ห้องสำเร็จ (prefab) `maps/build/room-<id>.json` = ตัวเลือกสำหรับห้องที่ใช้ซ้ำ วางด้วย `{ref, x, z, rot}` แล้ว "แตกห้องเข้าแผนที่" ได้ทุกเมื่อ (คัดลอกของเข้าไฟล์แผนที่ ไม่ผูกกับไฟล์ห้องแล้ว)
5. **แยกการเล่นกับหน้าตา**
   - การเล่น = ข้อมูลในไฟล์: พื้น/ความสูง, กำแพง, พื้นชั้นบน, เพดาน, ที่ชน, ของพังได้, จุดของโหมด
   - หน้าตา = `style` (ชื่อพรีเซ็ตที่เกมมีโค้ดวาดให้ เช่น `castle-stone`, `forest-mist`) + ของจากคลัง (`assets/mapkit/`) + `look`/`lt`/`fog`
   - ลุคที่เคยเขียนเป็นโค้ดเฉพาะแผนที่ → ทำเป็นพรีเซ็ตที่มีชื่อ ใช้ซ้ำได้ทุกแผนที่
6. **จุดของโหมดเป็นของในแผนที่** แต่ละโหมดประกาศว่าต้องมีอะไร (ตัวตรวจเช็กให้):
   - `siege`: แกน (เลข 1–N), จุดเกิดฝ่ายบุก/รับต่อเฟส, พื้นที่เล่นต่อเฟส, กำแพง/ประตูเป้าหมายที่ต้องพัง
   - โหมดอื่นตามที่มีใน MAP-BUILDER.md (`spawn`, `spawnR/B`, `espawn`, `ring`, `task`)
7. **ระบบเกมผูกด้วยแท็ก ไม่ผูกด้วยชื่อแผนที่** เช่น รั้วไหม้ได้ (`sys:'fence'` → js/12-efs), ผนังหินมีรอยแตก/ไหม้ (`sys:'stonewall'`), สะพานแตกแบบเปลือกไข่ (`sys:'eggshell'`), ของตกแต่งพังได้ตามชนิด `RPK` • ห้ามเขียน `if(map==='xxx')` ในโค้ดเกมใหม่
8. **งบ (ตัวตรวจเตือน)**: วงชน ≤ 2000, ไฟ ≤ 12, เพดานห้องมีหลังคา ≥ 20 ม., ที่บังกล้องรัศมี ≥ 0.7 ม. (14 px), ขนาด .glb (แผนที่ใหญ่ต้องแบ่งก้อน/บีบอัด)
9. **ทดสอบก่อนส่ง**: ตัวตรวจในแผงขวาไม่มี ✗ • ▶ ทดลองเล่น • headless เดินขึ้นบันได/บินชนเพดาน/กล้องไม่ทะลุผนัง (MAP-ROOMS §8)
10. **เน็ต**: ส่งเข้าเกม = `v` ใน manifest ขยับเอง (เครื่องลูกโหลดใหม่) • เปลี่ยนรูปแบบข้อมูลที่ส่งในเน็ต = bump `PREFIX` (js/10-net.js)

## 2. ช่องว่างตอนนี้ (Map Builder ยังทำไม่ได้ แต่แผนที่ fcs ใช้)

| สิ่งที่ fcs มี (โค้ด) | ที่อยู่ตอนนี้ | Map Builder ต้องเพิ่ม |
|---|---|---|
| แกน, จุดเกิดต่อเฟส, พื้นที่เฟส, กำแพง/ประตูเป้าหมาย | js/02-fcs.js `genFcs` → `MAPS.fcs.fcs` | ของชนิดใหม่ + พื้นที่เฟส + ส่งออก `siege:{}` |
| ห้อง (ผนัง ประตู พื้นชั้นลอย เพดาน เสา) | js/02-fcs-rooms.js + js/02-room-*.js | ห้อง prefab + เพดาน (`ceil`) |
| ของตกแต่งพังได้ (โต๊ะ ม้านั่ง เก้าอี้ ราว เสาใหญ่ ฯลฯ) | `RPK` js/02-fcs-rooms.js, ภาพ js/28-fcs-props.js | ชนิดของจาก `RPK` ในคลัง |
| รั้วไหม้ได้ | js/12-efs.js (อ่าน `MAPS.fcs.fcs.fences`) | แท็ก `sys:'fence'` |
| สะพาน L + แตกแบบเปลือกไข่ | js/02-fcs.js + js/12-fcs-bridge.js | แท็ก `sys:'eggshell'` บนพื้นชั้นบน/ชิ้นส่วน |
| หน้าตาปราสาท/ห้อง | js/28-fcs-build.js, js/28-fcs-castle.js | พรีเซ็ต `style` |
| ป่าสนหมอก (พื้นวาด หมอกตามตำแหน่ง ต้นไม้เสริม) | js/28-fcs-forest.js | พรีเซ็ต `style` + โซนหมอก + ต้นไม้เป็นของจริงในไฟล์ |
| ซากปราสาท/ต้นไม้/หินที่สุ่มด้วย seed | js/02-fcs.js | บันทึกเป็นของจริงในไฟล์ (ไม่สุ่มแล้ว) |
| ขนาด 630×225 ม. | — | .glb แบ่งก้อน/บีบอัด, Editor ลื่นพอ |

## 3. แผนย้าย fcs (ทีละรอบ ทุกรอบเล่นได้ตลอด)

| รอบ | งาน | เสร็จเมื่อ |
|---|---|---|
| 1 | Map Builder: ของโหมด siege + พื้นที่เฟส, เพดาน, ชนิดของจาก `RPK`, แท็ก `sys`, ช่อง `style` • ส่งออกข้อมูลพวกนี้ | วาง/แก้ได้ใน Tool และอยู่ในไฟล์ที่ส่งออก |
| 2 | เกม: โหมด siege อ่านแผนที่จากไฟล์ได้ (ตัวแปลงข้อมูลไฟล์ → รูปแบบที่ js/15-siege, js/12-efs, js/12-fcs-bridge ใช้) • bump PREFIX | แผนที่ทดสอบเล็ก ๆ จาก Map Builder เล่น siege ครบ 3 เฟส |
| 3 | ห้อง prefab ใน Map Builder + ย้าย Great Hall เป็นไฟล์ห้อง | Great Hall จากไฟล์เหมือนของเดิม (ภาพเทียบ + headless) |
| 4 | พรีเซ็ต `style` (ปราสาท, ห้อง, ป่าสนหมอก) จากโค้ดเดิม | ภาพเทียบแผนที่โค้ดกับแผนที่ไฟล์แทบไม่ต่าง |
| 5 | แปลง fcs ทั้งแผนที่เป็น `maps/build/fcs.json` (ตัวแปลงจาก `tools/fcs-to-mb.mjs`) + .glb แบ่งก้อน | เล่น siege บนแผนที่ไฟล์ได้ ภาพ/การเล่นตรงกับเดิม |
| 6 | สลับ siege ไปใช้แผนที่ไฟล์ แล้วเลิกใช้ js/02-fcs*.js, js/02-room-*.js, ท่อ mapedit → `tools/fcs-export.js` • อัปเดต MAP-ROOMS.md / CLAUDE.md | ไม่มีโค้ดสร้างแผนที่ fcs เหลือ |

แผนที่โค้ดอื่น (`castle`, `city`, `citytest`, `podroom`) ยังไม่ย้าย — ย้ายทีหลังถ้าผู้ใช้สั่ง
