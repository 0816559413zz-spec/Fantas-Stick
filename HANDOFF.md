> **Testing tips learned the hard way:**
> - The pane is often hidden → rAF stops. Drive frames yourself: `requestAnimationFrame=()=>0`, then loop `WD.hostStep(dt)`+`WD.render(dt,now)`. If screenshots time out or come out empty, `resize_window` 1280×720 and dispatch a `resize` event.
> - **Don't "freeze" time by rendering with a tiny dt for screenshots** — many emitters spawn a fixed count per *rendered frame*, so particles pile up (8000 cap) and you'll chase fake white-outs. Measure brightness deterministically instead (render once, `readPixels` with/without `Points` hidden).
> - CSS `var(--x)` holding `url(...)` resolves against `css/game.css`, not the page — always put absolute URLs in such variables (see `ICOBASE`).
> - `WD.setKit` on the host doesn't update the client's `KITS[id]` — also set `p.kt=p.kit` and call `WD.broadcastLobby()`.
> - Before every push: `node tools/check.js` (syntax of all js files joined) and load the page once (`typeof WD`) to catch load-order/TDZ errors. Errors say `game.js:N` → run `srcAt(N)` in the console for file:line (DevTools also shows real files via the source map).
> - Particle budget: new emitters that spawn every frame need nothing special (`VFXB` scales them); a one-shot effect spawned *inside* render code with <6 particles per call gets thinned at high FPS — wrap it in `vfxOnce(()=>...)`. Optional pretty layers: `if(vfxExtra())`.

## 4. Architecture (important)
- **Host-authoritative.** The host runs the whole simulation in `hostTick()` (setInterval 60 Hz) in a **2D plane** (x,y in pixels) plus height (`p.z` / `e.h` / `pr.h` in 3D units). Clients only send input (`{t:'in',i:INPUT}` every 30 ms) and render snapshots.
- Host broadcasts `makeSnap()` at 30 Hz (`{t:'s',s}`, with host time `T`, player fields packed by `packP`); clients buffer them (`SBUF`, ~50–120 ms behind) and predict their own movement (`predictMe`); the host itself renders from the same snapshot via `onSnap()` at 60 Hz. Events (`EVL`/`EVN` → `ev` array) drive effects/sounds through `fx(ev)`.
- Private per-player messages: `sendPriv(id,{...})` → client `{t:'priv',m}` → `onPriv(m)` (used for secret roles in the Voldemort mode). Never put secret data in the snapshot.
- Coordinates: 1 3D unit = 20 sim px. `tx(x)=(x-MW/2)/20`, `tz(y)=(y-MH/2)/20`. Current map size `MW,MH`, obstacles `OBS` (each `{x,y,r,k,hgt}`; flying higher than `hgt` passes over).
- Maps are generated deterministically (seeded `mulberry`) so every client builds the same world. `buildWorld(id)` rebuilds the 3D scene when `builtMap` differs from the lobby/snapshot map.
- Two canvases: `#gl` (WebGL 3D) and `#cv` (2D overlay for HUD, name tags, damage numbers). DOM overlays: menu, lobby, buff picker, results, meeting vote, guide, voice panel.
- **Menu & lobby render a separate 3D scene `stage`** (dark hall, gold rune dais, floating candles) via `renderStage()` — `rpass.scene` is swapped to `stage` for that frame. Characters there come from `makeStudent()` re-parented into `stage` (`STAGE.chars`). The map scene is only rendered in-game.
- **Performance (2026-10-16):** `antialias:false` (composer RT has no MSAA anyway), pixel ratio ≤1 by default, bloom rendered at half res (patched `bloom.setSize`), `PCFShadowMap` with `shadowMap.autoUpdate=false` (re-rendered every 2nd frame in auto, every frame in high), shadow map 2048 (4096 only on high for forest/pitch), light pool 6, `stoneMat` cached per (repeat,tint), and **`batchStatic(world, skip)`** merges every static, opaque, same-material mesh after `buildWorld` (castle ~480→~270 draw calls). Anything animated must go in the `skip` set (RUNE, CRYSTAL, SNITCH, FIREFLIES, CANDLES, BANNERS) or be a Sprite/InstancedMesh/transparent — **if you add a moving/toggled mesh to a map, add it to that skip list.**
- **Graphics quality** `QUAL` (menu button "กราฟิก", stored in `localStorage wd_gfx`): `auto` (default; `qualTick` drops render scale 1→0.55 when frames average >24 ms, raises it back when <18 ms), `high` (DPR up to 1.5, shadows every frame), `low` (scale 0.7, no shadows, no bloom). `applyQuality()` applies it.
- Camera: pointer lock; mouse → `yaw/pitch`; WASD is camera-relative (`INPUT.mx/my`); aim: `aimFromCrosshair(me,P,E)` raycasts from the camera through the screen-centre crosshair (hits players/enemies/`OBS` cylinders/ground, else 60 units) and sends that point as `INPUT.ax/ay` + height `INPUT.ah` (+ ground point `gx/gy`); `shoot()` flies from the hand straight through it, so bolts land on the crosshair despite the right-shoulder camera. Looking at the ground = the bolt hits the ground there. `INPUT.ap` (pitch) is only the fallback. Spells **auto-lock vertically** onto a foe within ~0.3 rad of the aim (`shoot()`).
