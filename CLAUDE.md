# CLAUDE.md

**แนวทางข้ามแชทที่ผู้ใช้สั่งให้เก็บ:** อ่าน `notes/PROJECT-DESIGN-DIRECTION.md` ก่อนออกแบบคลาส/สกิล/โหมด/แผนที่ คิดสกิลโดยมีบทบาทในโหมดปราสาทเป็นบริบท แต่รอคลาสเสร็จก่อน breakdown interaction ละเอียด ยังไม่มีผังปราสาทที่ยืนยัน ใช้ภาพหยาบช่วยคุยเรื่องพื้นที่ ข้อกำหนดนี้และคำสั่งผู้ใช้ล่าสุดมีผลเหนือขั้นอัตโนมัติด้านล่าง

1. **Read `HANDOFF.md` first** — architecture, testing tricks, current status. Then use `CODEMAP.md` to find code: read only the lines you need from the right `js/` file, never whole files (save tokens). Feature history is in `notes/` — open only when relevant.
2. **After every task:** run `node tools/check.js` (must say OK), `node tools/codemap.js`, and `node tools/fx-check.js` if you touched `assets/fx/` (no ✗ allowed), update `HANDOFF.md` (status, known issues, latest changelog line) + `notes/CHANGELOG.md`, then commit and push with the code.
3. The user doesn't code: do the work for them. **Reply language/style and session scope follow `guides/WORKFLOW-WITH-CLAUDE.md` (read it; it overrides the older Thai-reply rules here and in AGENTS.md):** Thai by default (user chose 2026-11-20), short, only what was asked; stay on this session's topic + related parts, off-topic ideas go to a separate/nested session; code comments short English.
3b. **Reply style:** see `guides/WORKFLOW-WITH-CLAUDE.md` §2 (short Thai: `แก้: ย้าย X ไป Y`). Technical terms, file names, commands, error messages stay verbatim. Risky/irreversible actions (delete data, force push) get a full, clear explanation. Commit messages and project docs are written normally.
4. Game = `index.html` (HTML + loader) + `css/game.css` + `js/NN-*.js` (joined into one module in `FILES` order — see HANDOFF §5). No build step. Bump `PREFIX` (`wizduel-th-vN-`, in `js/10-net.js`) whenever the snapshot/network protocol changes.
5. Commit with the repo-local noreply identity (check `git config --local user.email` first — the global one is a work email); pushing to `main` deploys GitHub Pages.
5b. **Tools = ศูนย์รวม Tool (`hub.html`, เปิดด้วย `Tools.bat`) — อ่าน `guides/TOOL-UI-RULES.md` ก่อนสร้าง/แก้ Tool:** UI โทนดำแบบ Studio มืออาชีพ (ห้ามธีมเกม) ใช้ `hub/tool-ui.css`, ลงทะเบียนใน `hub/tools.json`, และ Tool ต้องปิดเสียงเป็นค่าเริ่มต้น (สวิตช์ `hub/tool-sound.js`).
6. **VFX work goes through VFX Studio — read `VFX-STUDIO-CLAUDE.md` first:** effects are `assets/fx/**/*.fx.json` (format: `guides/FX-FORMAT.md`, read that instead of js), bound to events in `assets/fx/bind.json`. Check your work with contact sheets (`studio.html?fx=…&sheet=…&save=…` via `python tools/serve.py`, then Read `shots/…`) — see HANDOFF §0 tips.
7. **Bug notes:** the user writes problems + screenshots in `bugs.html` → read `bugs/BUGS.md` (open the pictures with Read). After fixing one: in `bugs/bugs.json` set `status:"fixed"` + a short Thai `reply`, then run `python tools/serve.py --bugs-md`.
7a. **Review Board:** งานที่รอผู้ใช้ดู/ตัดสินอยู่ใน `review.html` (กระดานรอรีวิว) → อ่าน `review/REVIEW.md` ทำเฉพาะสถานะ `change` (✏️ ขอแก้) ตามความเห็นผู้ใช้ (เปิดรูปด้วย Read). แก้เสร็จ: ใน `review/reviews.json` ตั้ง `status:"wait"` + `reply` ภาษาไทยสั้น ๆ แล้วรัน `python tools/serve.py --review-md`. **ห้ามตั้ง `ok` เอง** (ผู้ใช้กดผ่าน). ทำงานที่ผู้ใช้ต้องรีวิวเสร็จ (VFX/ท่า/สกิลใหม่) → เพิ่มรายการสถานะ `wait` พร้อมวิธีดู ไม่ต้องรอให้ผู้ใช้ถาม
7b. **Maps:** the user draws topdown reference maps in `mapedit.html` (Map Editor) → read `maps/MAPS.md`, then `maps/<id>.md` and open `maps/<id>.png` with Read. Format: `guides/MAP-FORMAT.md`. These are design references, not locked layouts.
7c. **Map Builder (แผนที่จริง):** `mapbuild.html` ทำแผนที่ที่เกมโหลดได้เลย (ต้นฉบับ `maps/build/<id>.json` → กด ⬆ ส่งเข้าเกม → `assets/maps/<id>.json` + `.glb` + manifest) → อ่าน `guides/MAP-BUILDER.md` ก่อนแก้ Tool หรือแก้แผนที่ให้ผู้ใช้. คลัง Asset: `assets/mapkit/kit.json` (`node tools/mapkit-gen.js`).
7d. **Sketch (สเก็ตช์):** ผู้ใช้วาด/เขียน/ลูกศร/วงกลมสื่อสารกับ Claude ใน `sketch.html` → อ่าน `sketch/SKETCH.md` แล้ว `sketch/<id>.md` และเปิด `sketch/<id>.png` ด้วย Read (ภาพ = สิ่งที่ผู้ใช้ต้องการ/ปัญหา, ลูกศร/วงกลม = ชี้จุด, เลข = ลำดับ, โน้ตในไฟล์ .md = คำอธิบาย). รูปพื้นหลังต้นฉบับอยู่ `sketch/img/`.
7e. **Map rule — room pieces (ผู้ใช้สั่ง 2026-11-20):** ห้อง/ลานในแผนที่ปราสาททำเป็นชิ้นแยก หนึ่งห้อง = หนึ่งไฟล์ `js/02-room-<id>.js` ใช้พิกัดภายในห้อง ประตูเป็นจุดต่อ แยก `gen` (การเล่น) กับ `view` (หน้าตา) เพื่อย้าย/เปลี่ยนสไตล์ทีละห้องได้ — อ่าน `guides/MAP-ROOMS.md` ก่อนทำ/แก้ห้องหรือแผนที่ FCS
8. **VFX storyboards:** the user plans skill VFX shot by shot in `storyboard.html` (synced between machines through git — **`git pull` first**, see `guides/STORYBOARD-SYNC.md`) → read `storyboard/sb-<id>.md` (open the sketches with Read) and follow `VFX-STUDIO-CLAUDE.md` §4b; write results back into `storyboard/boards.json`, then `python tools/serve.py --sb-md`.
9. **Always show VFX to the user in VFX Studio:** whenever you make or change an effect, open it in the studio (`studio.html?fx=<group>/<name>` in the browser pane) so the user sees how it looks, and send the contact sheet in chat. Do this before asking for approval (VFX-STUDIO-CLAUDE.md §4 step 9).
10. **Game Studios team (from [Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios), MIT, `.claude/CCGS-LICENSE`):** `.claude/agents/` (34 specialist subagents — game-designer, systems-designer, qa-lead, technical-artist, …), `.claude/skills/` (74 slash commands — `/brainstorm`, `/design-review`, `/balance-check`, `/bug-triage`, `/playtest-report`, …), plus their `rules/`, `docs/`, `scripts/` and `project.yaml`. Only the agents + skills were taken: no hooks, no settings, and Godot/Unity/Unreal agents left out. This game is browser JS + three.js, not an engine project. Where their docs say "ask before every write" or assume `src/`/an engine, the rules in this file win (do the work for the user, keep our `js/`, tools and workflow).
