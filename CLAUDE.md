# CLAUDE.md

1. **Read `HANDOFF.md` first** — architecture, testing tricks, current status. Then use `CODEMAP.md` to find code: read only the lines you need from the right `js/` file, never whole files (save tokens). Feature history is in `notes/` — open only when relevant.
2. **After every task:** run `node tools/check.js` (must say OK), `node tools/codemap.js`, and `node tools/fx-check.js` if you touched `assets/fx/` (no ✗ allowed), update `HANDOFF.md` (status, known issues, latest changelog line) + `notes/CHANGELOG.md`, then commit and push with the code.
3. The user speaks Thai and doesn't code: reply in Thai, keep it simple, and do the work for them.
4. Game = `index.html` (HTML + loader) + `css/game.css` + `js/NN-*.js` (joined into one module in `FILES` order — see HANDOFF §5). No build step. Bump `PREFIX` (`wizduel-th-vN-`, in `js/10-net.js`) whenever the snapshot/network protocol changes.
5. Commit with the repo-local noreply identity (check `git config --local user.email` first — the global one is a work email); pushing to `main` deploys GitHub Pages.
6. **VFX work goes through VFX Studio — read `VFX-STUDIO-CLAUDE.md` first:** effects are `assets/fx/**/*.fx.json` (format: `FX-FORMAT.md`, read that instead of js), bound to events in `assets/fx/bind.json`. Check your work with contact sheets (`studio.html?fx=…&sheet=…&save=…` via `python tools/serve.py`, then Read `shots/…`) — see HANDOFF §0 tips.
7. **Bug notes:** the user writes problems + screenshots in `bugs.html` → read `bugs/BUGS.md` (open the pictures with Read). After fixing one: in `bugs/bugs.json` set `status:"fixed"` + a short Thai `reply`, then run `python tools/serve.py --bugs-md`.
8. **VFX storyboards:** the user plans skill VFX shot by shot in `storyboard.html` (synced between machines through git — **`git pull` first**, see `STORYBOARD-SYNC.md`) → read `storyboard/sb-<id>.md` (open the sketches with Read) and follow `VFX-STUDIO-CLAUDE.md` §4b; write results back into `storyboard/boards.json`, then `python tools/serve.py --sb-md`.
9. **Always show VFX to the user in VFX Studio:** whenever you make or change an effect, open it in the studio (`studio.html?fx=<group>/<name>` in the browser pane) so the user sees how it looks, and send the contact sheet in chat. Do this before asking for approval (VFX-STUDIO-CLAUDE.md §4 step 9).
10. **Game Studios team (from [Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios), MIT, `.claude/CCGS-LICENSE`):** `.claude/agents/` (34 specialist subagents — game-designer, systems-designer, qa-lead, technical-artist, …), `.claude/skills/` (74 slash commands — `/brainstorm`, `/design-review`, `/balance-check`, `/bug-triage`, `/playtest-report`, …), plus their `rules/`, `docs/`, `scripts/` and `project.yaml`. Only the agents + skills were taken: no hooks, no settings, and Godot/Unity/Unreal agents left out. This game is browser JS + three.js, not an engine project. Where their docs say "ask before every write" or assume `src/`/an engine, the rules in this file win (do the work for the user, keep our `js/`, tools and workflow).
