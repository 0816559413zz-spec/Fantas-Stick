## 1. ตอนนี้ระบบ VFX ทำงานยังไง (สรุปจากการอ่านโค้ด)

```
host (จำลองเกม) ──event {k:'efx', z:'dfboom', x,y,h,a,r,...}──▶ client
                                                                 │
   efxFX(ev)  js/25-efx.js  ← โค้ดเขียนมือ ~92 case (1 case ต่อ 1 เอฟเฟกต์)
      ├─ helper ทั่วไป: burst / smoke / flame → PARTS (อนุภาค, js/30)   ring / FX.flashSprite / FX.flashLight (js/30)
      ├─ helper เฉพาะธาตุ: fireBlast / fireCrackWeb / fireGeyser (js/42) • iceBurst / glacierMist (js/43) • tbolt (js/20) • trail (js/44)
      ├─ EFXAUG → playFx('fire_big') = สูตรข้อมูล (จานสี × แม่แบบ, js/44) เล่นทับเพิ่ม
      └─ fileFx('vfx_<z>') = ไฟล์ .glb / flipbook จาก Blender (js/22) ถ้ามีใน manifest
ภาพต่อเนื่องทุกเฟรม (ออร่า โล่ ร่างอัลติ กระสุน): pyroFX / frostFX / stormFX / syncProj — โค้ดล้วน
วาดผล: ฉาก → FXPass (อนุภาคนุ่ม แตะพื้นแล้วจาง) → bloom → GradePass (โทนสี + เอฟเฟกต์ทั้งจอ)  (js/27)
งบ: VFXB ปรับจำนวนอนุภาคตาม FPS/ระดับกราฟิก • vfxOnce / vfxExtra
```

**ของใหม่จากเพื่อน (ดึงมา 2026-10-19 ตอนเขียนแผน):** ไฟ 3 มิติจริงแบบ volumetric `fireVol` / `fireVolTemp` (js/42) ใช้กับแนวไฟ เปลือกไฟหุ้มตัว เสาไฟ • ภาพ flipbook ไฟจาก Blender `vfx/tex_fire.png` (manifest `ptex`) + สคริปต์ `assets/src/fire_flipbook_build.py`, `tools/pack_flipbook.py` • กฎใหม่ใน VFX.md: **ไฟก้อนใหญ่/แนวไฟห้ามใช้แผ่นภาพ** (ผู้ใช้บอกว่าดู 2D) → ใช้ `fireVol` — สตูดิโอต้องมีชั้น `mesh` วัสดุ **`volume`** (กล่อง raymarch ของ `fireVol`) ตั้งแต่ขั้น 4 และให้ `emit` เลือก flipbook `fire`/`smoke` ได้

**จุดแข็งที่ต้องเก็บไว้:** renderer + post pipeline ดีแล้ว, shader ไฟ/น้ำแข็งสวย, อนุภาคสมจริงขึ้นแล้ว (ramp/erosion/curl/premultiplied), ระบบงบ, `playFx` พิสูจน์แล้วว่า "เอฟเฟกต์เป็นข้อมูล" ใช้ได้

**ปัญหา (ทำไมทำ VFX ช้า):**
| # | ปัญหา | ผลที่เกิด |
|---|---|---|
| 1 | เอฟเฟกต์ส่วนใหญ่เป็น **โค้ดเขียนมือ** (ตัวเลขฝังในบรรทัดยาว ๆ) | คนไม่เขียนโค้ดแตะไม่ได้ • Claude ต้องอ่านโค้ดเยอะ เปลืองโทเคน แก้แล้วพังง่าย |
| 2 | **ดูผลยาก**: ต้องเข้าเกม → ห้องฝึก → ร่ายท่า → ถ่ายภาพทันเวลา | รอบแก้หนึ่งครั้งหลายนาที • ภาพนิ่งจับจังหวะผิด • "หยุดเวลา" แล้วอนุภาคกองจนจอขาวปลอม (บทเรียนใน HANDOFF) |
| 3 | Claude **มองไม่เห็นเอง** ว่าสวย/ขาวโพลน/บังตัวละครไหม | ต้องรอผู้ใช้ส่งรูปมาติ |
| 4 | `playFx` มีแค่ชั้นแบน ๆ (แฟลช ประกาย วงพื้น) — **รูปทรง 3D** (ลูกไฟ กำแพง หนาม ปีก รอยฟัน) ยังต้องเขียน shader/mesh ในโค้ด | ของที่ "ดูแพง" ทำได้เฉพาะคนเขียนโค้ด |
| 5 | Blender ทำได้แต่โมเดล/animation ไม่เห็นสีจริง/แสงฟุ้ง/อนุภาคของเกม ต้อง export-โหลด-ลองวนไป | ช้า และเรียนยาก |

## 2. แนวคิดหลัก

1. **เอฟเฟกต์ = ไฟล์ข้อมูล 1 ไฟล์** (`assets/fx/<ธาตุ>/<ชื่อ>.fx.json`) = รายการ **ชั้น (layer)** วางบน **เส้นเวลา** — แบบ After Effects / Unity Particle System แต่เรียบกว่ามาก
2. **runtime เดียว** ในเกม (`fxPlay`) อ่านไฟล์แล้วสร้างภาพด้วยของที่เกมมีอยู่แล้ว (PARTS, fireMat, iceShaderMat, tbolt, trail, ring, light, screen) → **ไม่มีระบบภาพใหม่ซ้อน** ภาพในสตูดิโอ = ภาพในเกม 100%
3. **VFX Studio** = หน้าเว็บ `studio.html` ในโปรเจกต์ (เปิดผ่าน server เดิม) โหลดโค้ดเกมจริงทั้งหมด + แผงแก้ไข: กดเล่น ลากเส้นเวลา แก้แถบเลื่อน เห็นผลทันที
4. **ผูกกับสกิลด้วยตาราง** (`assets/fx/bind.json`): `"efx:dfboom" → "fire/dfboom"` — ไม่ต้องแก้โค้ดสกิล • เลือกได้ว่า **เพิ่มทับ** ของเดิม หรือ **แทนที่**
5. **Claude-first**: ทุกอย่างที่คนกดได้ในสตูดิโอ Claude ทำได้ด้วยการแก้ไฟล์ + URL/console API + ภาพสรุปทั้งไทม์ไลน์ + ตัวเลขตรวจคุณภาพ

**Blender เหลือหน้าที่เดียว:** ปั้น *รูปทรงพิเศษ* (ปีก กรงเล็บ ดาบ หนามรูปแปลก) เป็น `.glb` แล้วลากเข้าสตูดิโอ — สี วัสดุ จังหวะ อนุภาค แสง ทำในสตูดิโอทั้งหมด

### 3.2 กติกาทั่วไป (ทุกชั้น)
| ฟิลด์ | ความหมาย |
|---|---|
| `id` | ชื่อชั้น (ใช้ใน timeline, solo/mute, อ้างอิงจากชั้นอื่น) |
| `t` | ชนิดชั้น (§3.3) |
| `at`, `life` | เริ่มที่วินาทีเท่าไร, อยู่นานเท่าไร (`loop:true` = วนจนเอฟเฟกต์ถูกสั่งหยุด — ใช้กับออร่า/โซน/บัฟ) |
| `pos`, `rot` | ตำแหน่ง/หมุนใน **กรอบของเอฟเฟกต์**: หน่วย **เมตร** (= หน่วย 3D), **+z = ทิศเล็ง `a`**, +y = ขึ้น, 0 = จุดของ event บนพื้น |
| `follow` | ติดตามอะไร: `none` (ค่าเริ่ม) / `caster` / `target` / `hand` / `wand` / `head` / `feet` / `chest` / `proj` (กระสุน) |
| `x:1` | ชั้นเสริม — ปิดเมื่อกราฟิก "ประหยัด" (แทน `vfxExtra`) • `near:35` = เล่นเฉพาะเมื่อห่างกล้อง ≤ 35 เมตร • `own:1` = เฉพาะเอฟเฟกต์ของเราเอง |
| ค่าตัวเลข | ตัวเลขธรรมดา • `[min,max]` = สุ่มในช่วง • `"r*0.55"` = สูตรง่าย ๆ จาก `params` (+ − × ÷ เท่านั้น) • **เส้นโค้งตามอายุชั้น** `{"0":0.2,"0.3":1,"1":0}` (เวลา 0–1 → ค่า, ใส่ `"ease":"out"` ได้) • เส้นโค้งคูณสูตรได้ด้วย `"x":"r"` |
| สี | `#rrggbb` หรือตัวแทนจานสี `$core $hi $main $deep $light` (จานสี `pal` ของไฟล์ — เปลี่ยนธาตุทั้งเอฟเฟกต์ได้ด้วยการเปลี่ยน `pal` คำเดียว) • `ramp:[...]` = ไล่หลายสีตามอายุ |
| `seed` | ระดับไฟล์ — ใส่แล้วการสุ่มเหมือนเดิมทุกครั้ง (ใช้ตอนถ่ายภาพเทียบ) |

### 3.3 ชนิดชั้น (เน้น 3D)
| `t` | ทำอะไร | สร้างจากของเดิมในเกม |
|---|---|---|
| **`mesh`** | **รูปทรง 3D + วัสดุ shader** — หัวใจของ VFX แบบ 3D • `shape`: `sphere` `dome` `disc` `ring` `cylinder` `tube` `cone` `torus` `crescent` (เสี้ยว/รอยฟัน) `spikes` (มงกุฎหนาม) `beam` (ลำแสงยาว) `ribbon` (แถบตามเส้นทาง `path`) `lathe` (หมุนรอบแกนจากเส้นโปรไฟล์) `plane` หรือ `glb:mesh_xxx` (จาก Blender) • `mat.type`: `fire` `volume` (ไฟ 3 มิติจริง `fireVol`) `ice` `energy` (เรืองขอบ fresnel + noise ไหล) `dissolve` `solid` `glass` `flip` (ภาพ flipbook) • ค่าตามเวลา: `scale` `op` `rot`/`spin` `scroll` (uv ไหล) `dissolve` `col` `heat` | `fireMat`, `iceShaderMat`, `iceModel`, `crescentGeo` |
| **`emit`** | ตัวปล่อยอนุภาค 3D • `from.shape`: `point` `sphere` `hemisphere` `ring` `disc` `cone` `box` `line` `mesh` (ผิวของชั้น mesh อื่น) • `burst` (ครั้งเดียว) / `rate` (ต่อวินาที, ผ่าน VFXB อัตโนมัติ) • `dir`: `out` `in` `up` `aim` `tangent` (หมุนวน) • `look.type`: `glow` `spark` `streak` `ring` `flake` `smoke` `fire` `flip:<ชื่อ>` • `ramp`, `size` (เส้นโค้ง), `gravity`, `drag`, `curl`, `spin`, `fin` • `onDeath` = ปล่อยเอฟเฟกต์ย่อยตอนเม็ดตาย (ขั้นหลัง) | `PARTS` (+ ramp/erosion/curl/flipbook ที่มีแล้ว) |
| `trail` | หางแสงตามชั้นอื่นที่ขยับ (`of:"ball"`) หรือ **รอยฟัน** `sweep` ตามมุม (`from`→`to` องศา, รัศมี, ความกว้าง) | `trailNew/trailPoint` |
| `bolt` | สายฟ้าหนา จาก A→B / แตกกิ่ง / พันรอบชั้นอื่น | `tbolt`, `tboltP` |
| `decal` | ลายบนพื้นตามความสูงพื้นจริง: `scorch` `rune` `crack` `frost` `ring_rune` หรือภาพ `img:` | `scorch`, `fireRune`, `fireCrackWeb`, `makeDfCircle` |
| `debris` | ชิ้นส่วน 3D กระเด็นแล้วตก: `rock` `ice` `plate` `glb:` | `rockChunks`, `iceBit` |
| `mist` | หมอกต่ำ (instanced) | `glacierMist` |
| `ring` / `flash` / `halo` | วงกระแทกบนพื้น / แกนแว้บ / ฮาโลฟุ้ง (แบบ `playFx` เดิม) | `SHAPES_Q`, `FX.flashSprite` |
| `light` | ไฟจุดส่องฉาก (`int` ≤ 2.5 แนะนำ) | `FX.flashLight` |
| `screen` | `shake` `flash` `radial` `kick` `hurt` (+ `own`/`near`) | `screenFlash/Radial/Kick` |
| `sound` | เสียง `snd(name)` | `snd` |
| **`use`** | ใส่เอฟเฟกต์อื่นทั้งก้อน (prefab) เช่น `common/crack_web`, `ice/crown` พร้อมส่ง params | — |
| `code` | ทางหนีไฟ: เรียกฟังก์ชันที่ลงทะเบียนไว้ (`FXCODE.xxx`) — สำหรับของเฉพาะทางที่ยังไม่มีชนิดชั้น | ฟังก์ชันเดิมทั้งหมด |

**ภาพต่อเนื่อง** (ออร่า โล่ ร่างอัลติ กระสุน): ไฟล์เดียวกันแต่ชั้นเป็น `loop:true` + `follow` → โค้ดเรียก `h=fxPlay('fire/blaze_aura',{follow:id})` ตอนเริ่ม และ `fxStop(h)` ตอนจบ (มีช่วง `start` / `loop` / `end` เหมือนไฟล์ Blender)

### 3.4 ไฟล์ผูก `assets/fx/bind.json`
```json
{
  "efx:dfboom":   {"fx":"fire/dfboom", "mode":"add", "p":{"r":"ev.r/20"}},
  "efx:slam3":    {"fx":"ice/slam3",   "mode":"replace"},
  "proj:spark:hit": {"fx":"fire/spark_hit"},
  "buff:blaze":   {"fx":"fire/blaze_aura", "follow":"caster"}
}
```
`mode:"add"` = เล่นเพิ่มจากภาพโค้ดเดิม • `"replace"` = ข้าม `case` ในโค้ด (ทำทีละท่าได้ ไม่ต้องย้ายทีเดียว) • ค่าจาก event (`ev.r`, `ev.a`, `ev.col`) ส่งเข้า params ได้

## 4. Runtime ในเกม — `js/45-fx-runtime.js` (ไฟล์ใหม่ ต่อท้าย FILES)
- `fxPlay(name, {x,y,h,a,s,col,p,follow,seed})` → handle • `fxStop(h, {now})` • `fxBound(kind, key, ev)` (เรียกจาก `efxFX`/`fx` บรรทัดเดียว)
- โหลดไฟล์ครั้งแรกที่ใช้ + `prefetch` ตอนสร้างแผนที่ (ตาม kit ของผู้เล่นในห้อง) • ไฟล์ยังไม่มา = ใช้ภาพโค้ดเดิม
- **ไม่สร้าง material/geometry ต่อเฟรม**: แคชตามคีย์ (`shape+พารามิเตอร์`, `mat.type+ค่า`) • mesh ซ้ำจำนวนมากใช้ InstancedMesh
- ผ่านงบเดิมทั้งหมด: อนุภาคเข้า `PARTS` (VFXB), `x:1` = `vfxExtra`, ระยะไกลลดรายละเอียดเอง (LOD)
- **ฝั่ง client ล้วน — ไม่เปลี่ยนโปรโตคอล** (ไม่ต้อง bump PREFIX)
- ทดสอบความเท่ากัน: แปลง `VFXTPL`/`VFXR` เดิมเป็นไฟล์ `assets/fx/tpl/*.fx.json` แล้วให้ `playFx` เรียก runtime ใหม่ → ภาพต้องเหมือนเดิม (วัดด้วย §6.3)

**ของที่ทำให้ "ง่ายกว่า Blender 10 เท่า":**
- **เริ่มจากแม่แบบ**: ระเบิด / กระแทก / รอยฟัน / ลำแสง / ออร่า / วงพื้น / กระสุน / บัฟ / อัญเชิญ / อัลติ → ได้เอฟเฟกต์สวยตั้งแต่วินาทีแรก แล้วค่อยปรับ
- **ปุ่มธาตุ** เปลี่ยน ไฟ ↔ น้ำแข็ง ↔ สายฟ้า ทั้งเอฟเฟกต์ในคลิกเดียว (จานสี) • **ปุ่มความแรง** (เบา/กลาง/จัดเต็ม) คูณจำนวน/ขนาด/ความสว่างพร้อมกัน
- ทุกค่าเป็น **แถบเลื่อน + ตัวเลือกรูปภาพ** (รูปทรงมีภาพย่อ) • ค่าตามเวลา = **เส้นโค้งลากจุดได้** • สี = จานสีธาตุก่อน แล้วค่อยวงล้อสี
- **เส้นเวลา**: ลากแถบเลื่อนจังหวะ/ยืดอายุ, ลากหัวเล่น (scrub) ดูทีละเฟรม, เล่นช้า 0.1×–1×, วน, ซ่อน/เดี่ยวรายชั้น (👁 / S)
- **ดูในสภาพจริง**: คนร่าย+หุ่นเป้าจริง, มุมกล้องเกม, พื้นสว่าง/มืด/แผนที่จริง, สลับระดับกราฟิก, **A/B เทียบ** กับภาพเดิม/เวอร์ชันก่อน
- **เตือนอัตโนมัติ** (แถบแดงที่ชั้น): จอขาวโพลน, บังตัวละครนานเกิน 0.3 วิ, อนุภาคเกินงบ, ไฟจุดแรงเกิน, ขนาด flash เกิน
- **ลากไฟล์ใส่จอ**: `.glb` → ชั้น mesh • `.png` ตาราง → flipbook
- **บันทึก**: กดครั้งแรกเลือกโฟลเดอร์โปรเจกต์ (Chrome/Edge) แล้วบันทึกตรงลง `assets/fx/` • บันทึกร่างอัตโนมัติในเครื่อง • ย้อน/ทำซ้ำ (Ctrl+Z / Ctrl+Y)
- **ลองในเกม**: เปิดห้องฝึกพร้อมเอฟเฟกต์นี้ผูกกับท่าที่เลือก
- ภาษา: ป้ายไทย + ชื่ออังกฤษเล็ก ๆ ใต้ (ตรงกับชื่อในไฟล์ — คนกับ Claude คุยเรื่องเดียวกันได้)

## 6. ทำให้ Claude ทำงานสะดวกที่สุด

### 6.1 อ่านน้อย เขียนถูก
- **`FX-FORMAT.md`** สั้น ๆ: ทุกฟิลด์ หน่วย ค่าเริ่ม ตัวอย่าง 1 บรรทัด + **`tools/fx-schema.json`** (JSON Schema มีคำอธิบายทุกฟิลด์) → Claude อ่านไฟล์เดียวรู้ครบ ไม่ต้องเปิดโค้ด js
- เอฟเฟกต์ 1 ท่า = ไฟล์เล็ก 30–80 บรรทัด → แก้ทีละไฟล์ ไม่ต้องหาในโค้ด 9,000 บรรทัด
- `CODEMAP.md` มีหมวด fx: รายชื่อไฟล์ fx + event ที่ผูก (สร้างอัตโนมัติ)

### 6.2 ตรวจเองได้ทันที (ไม่ต้องเปิดเกม)
- **`node tools/fx-check.js`**: ตรวจรูปแบบ ฟิลด์ผิด/สะกดผิด, ไฟล์/โมเดลที่อ้างถึงมีจริง, ชื่อ event ใน `bind.json` มีอยู่จริงในโค้ด host, **ตรวจงบ** (burst เกิน, ไฟจุดเกิน 3 ดวง, flash ใหญ่เกิน, screen flash > 0.06, ชั้นบังตัวละครยาว) → ข้อความบอกไฟล์:ชั้น:ฟิลด์ + วิธีแก้

### 6.3 "มองเห็น" ด้วยภาพเดียว + ตัวเลข
- **URL สำหรับถ่ายภาพ**: `studio.html?fx=fire/dfboom&sheet=0,0.05,0.15,0.3,0.6,1.2&cam=game&bg=dark`
  → วาด **แผ่นภาพสรุปทั้งไทม์ไลน์** (6–8 เฟรมเรียงเป็นตาราง + ป้ายเวลา + ตัวเลข) → ภาพเดียวเห็นทั้ง ง้าง → กระแทก → สลาย
- **จำลองแบบแน่นอน (deterministic)**: กระโดดไปเวลา t = จำลองจาก 0 ด้วย dt คงที่ + seed คงที่ → ภาพเดิมทุกครั้ง • **แก้ปัญหา "หยุดเวลาแล้วอนุภาคกอง" ที่บันทึกไว้ใน HANDOFF โดยตรง**
- **ตัวเลขคุณภาพ** (`STUDIO.metrics()` คืน JSON): ความสว่างสูงสุด/เฉลี่ย, % พิกเซลขาวจ้า (เกณฑ์จอขาว), % ที่บังกรอบตัวละครต่อเวลา, จำนวนอนุภาค/draw call/ms ต่อเฟรม → Claude ตัดสินได้เองว่า "ขาวเกิน" หรือ "บังตัว"
- **บันทึกภาพลงไฟล์**: `tools/serve.py` (แทน `python -m http.server`) = เสิร์ฟเหมือนเดิม + รับ POST `/shot` เก็บ PNG ลง `shots/` (git-ignore) → Claude ใช้ Read ดูรูปได้ แม้แผงเบราว์เซอร์ถูกซ่อน (แก้ปัญหา screenshot timeout)
- **เทียบก่อน/หลัง**: `&ab=HEAD~1` หรือ `&ab=file:old.fx.json` → ภาพซ้าย/ขวา + ตัวเลขต่างกัน

### 6.4 ทำงานคู่กันแบบสด
- สตูดิโอเฝ้าดูไฟล์ที่เปิดอยู่ (โหลดใหม่ทุก ~0.5 วิ เมื่อไฟล์เปลี่ยน) → **Claude แก้ JSON ผู้ใช้เห็นทันทีบนจอ** • ผู้ใช้ลากแถบเลื่อน → ไฟล์เปลี่ยน → Claude เห็นใน git diff ว่าผู้ใช้ปรับอะไร
- console API `window.STUDIO`: `load(name)` `play()` `seek(t)` `set('ball.mat.heat',0.3)` `sheet([...])` `metrics()` `shot(name)` `bind(event,fx)`

### 6.5 แม่แบบคำสั่ง
- `notes/prompts/fx-template.md`: วิธีแปลง "แบบฟอร์มขอเอฟเฟกต์" (VFX.md §8) → ไฟล์ fx ทีละขั้น: เลือกแม่แบบ → จานสี → ชั้น 3D หลัก → อนุภาค → แสง/จอ → sheet → metrics → ปรับ → bind → ลองในเกม

## 8. กติกา/ความเสี่ยง
- **ไม่แตะเกมเพลย์** (ดาเมจ เวลา ระยะ) — ไฟล์ fx เป็นภาพล้วน ระยะ/รัศมีมาจาก event
- **ไม่เปลี่ยนโปรโตคอล** — ทั้งหมดอยู่ฝั่ง client
- โหลดไฟล์ fx ช้ากว่าโค้ด → ใช้ภาพโค้ดเดิมจนไฟล์พร้อม (เหมือน `fileFx`) + prefetch ตอนเข้าห้อง
- ประสิทธิภาพ: runtime ต้องแคชทุกอย่าง, วัดด้วย `tools/bench-vfx.js` ก่อน/หลังทุกขั้น (เป้า: ไม่ช้ากว่าโค้ดเขียนมือเกิน 5%)
- สตูดิโอโหลดโค้ดเกมทั้งหมด → ห้ามเริ่มเครือข่าย (PeerJS) / เพลง / เมนู ในโหมดสตูดิโอ
- ไฟล์ทั้งหมดอยู่ใน repo สาธารณะ → ภาพ/โมเดลต้องทำเองหรือ CC0
- รูปแบบไฟล์มีเลขเวอร์ชัน `v` — เปลี่ยนโครงสร้างเมื่อไรให้มีตัวแปลงอัตโนมัติ

## 11. ส่วนที่ 2 — สร้าง asset เองในแอปเดียว (โมเดล + ภาพ) ✅ ทำแล้ว 2026-10-20
ผู้ใช้: "อยากให้สร้าง VFX ได้ด้วย มี asset และเครื่องมือสำคัญแบบ Blender แต่ใช้ง่ายกว่า 10 เท่า อยู่ในแอปเดียวกัน"

**แนวคิด:** งาน VFX ใน Blender ของโปรเจกต์นี้มี 2 แบบ — (1) ปั้นรูปทรงประกอบเอฟเฟกต์ (หนามน้ำแข็ง มงกุฎหนาม ปีก กรงเล็บ ดาบ ริบบิ้นวน) ด้วยสคริปต์ `assets/src/*_build.py` และ (2) ทำภาพ flipbook ไฟ/ควันจากการจำลอง Mantaflow (`fire_flipbook_build.py`) → ทั้งสองอย่างย้ายมาอยู่ในสตูดิโอ:
